AWS Security Pillar 4: Detection

Source: AWS Well-Architected Framework, Security Pillar, "Detection", SEC04. Own-words summary, much shorter than the source. Previous: AWS Security Pillar 3: Permissions Management. Next: AWS Security Pillar 5: Infrastructure Protection.

Takeaways
  • Detection finds misconfigurations, threats and unexpected behaviour. It supports quality, legal and compliance needs and feeds incident response.
  • Collect logs before you need them: you cannot reconstruct activity from logs you never kept.
  • Gather logs and findings in standard places (a Log Archive account, S3, Security Lake) so alerts from different sources can be joined.
  • Automated remediation is useful only if it is tested and overseen.

4.1 The idea

  • Watch for unexpected or unauthorised activity (GuardDuty), for mutating API calls your workload should not make, and for API calls that change the security posture.
  • Review the detection mechanisms regularly against internal and external policies, and alert automatically on defined conditions so people or tools can investigate.

4.2 SEC04-BP01 Configure service and application logging (risk: high)

  • Keep security event logs from services and applications. They serve audit, investigation and operational uses and are often required by governance, risk and compliance standards.
  • Anti-patterns: logs kept forever or deleted too soon; everyone can read them; log governance done manually.
  • Choose sources for your use cases:
    • CloudTrail:
      • API calls. Management events are on by default with 90-day history
      • create a trail (to S3, optionally CloudWatch Logs) for longer retention and data events
      • or use CloudTrail Lake (up to seven years, SQL queries).
    • VPC Flow Logs (network traffic) and Route 53 resolver query logs (DNS): AWS recommends them for VPC users; scope flow logs to control cost.
    • These three are the basic sources for investigations. Security Lake can collect and normalise them (Parquet, OCSF).
    • Others: load balancer logs, WAF logs, Config recorder, GuardDuty findings, EKS audit logs, EC2 OS and application logs, RDS logs, Network Firewall logs.
  • Storage and query:
    • S3 is cheap and durable with lifecycle rules; query with Athena or OpenSearch.
    • CloudWatch Logs has built-in Logs Insights; archive older logs to S3.
    • Typical practice: three months to a year readily queryable, up to seven years retained, driven by statutory, regulatory and business needs.

4.3 SEC04-BP02 Capture logs, findings and metrics in standardised locations (risk: medium)

  • Anti-pattern: teams each own their logging and metrics, so nothing lines up.
  • Steps:
    1. Create Log Archive and Security Tooling accounts under a security OU (Control Tower makes them for you).
    2. Choose the standard data location: a data lake approach, a third-party product or Amazon Security Lake. Capture data from every opted-in Region, even unused ones.
    3. Configure every source to publish there, in a consistent format.

4.4 SEC04-BP03 Correlate and enrich security alerts (risk: low)

  • One incident often triggers alerts in several systems; joining them shows the full picture.
  • Anti-pattern: different groups investigate different systems' alerts separately.
  • Steps:
    • list alert sources and how each describes identity, action and resource
    • collect alerts with Security Hub CSPM, EventBridge or CloudWatch
    • enrich with CloudTrail, VPC Flow Logs, Route 53 resolver logs and application logs (one Security Lake integration can serve several)
    • use Amazon Detective, a SIEM, or a Lambda that runs Athena queries.

4.5 SEC04-BP04 Initiate remediation for non-compliant resources (risk: medium)

  • Define remediations in code so the response is quick and consistent, manual or automatic.
  • Anti-pattern: automation that was never thoroughly tested and validated.
  • Steps:
    1. Consolidate alerts in Security Hub CSPM and prioritise.
    2. Build remediations with Systems Manager and Lambda.
    3. Trigger via Systems Manager custom actions publishing to EventBridge (manual or automatic); use SNS to notify the security or incident team where a human must decide.
    4. Review remediation logs (CloudWatch Logs; outcomes as Security Hub finding notes) and improve.
  • Keep oversight: automated responses must be effective, accurate and in line with policy and risk appetite.

Summary points

  • Turn on CloudTrail, VPC Flow Logs and DNS logs everywhere first.
  • Put the logs in an account the workload teams cannot change.
  • Correlate before you escalate; remediate by code, but test it.
Terms to carry forward
  • CloudTrail: record of AWS API calls; CloudTrail Lake adds long retention and SQL.
  • Security Lake: collects and normalises security logs (OCSF, Parquet).
  • GuardDuty, Detective, Security Hub CSPM: threat detection, investigation graph, findings hub.
  • SIEM: security information and event management tool.
  • Log Archive account: separate account holding logs.
