Core Java 1: An Introduction to Java

Source: Cay S. Horstmann, Core Java, Volume I: Fundamentals, 14th ed. (Pearson, 2025), ch. 1. Next: Core Java 2: The Java Programming Environment.

Takeaways
  • Java is a platform, not just a language. A clean language, a huge standard library and a runtime that gives security, portability and garbage collection are what made it succeed.
  • The designers' 11 buzzwords describe the original goals; Horstmann marks which ones aged well (portable, robust, high-performance, multithreaded) and which did not (secure sandbox, applets).
  • Source compiles to bytecode; the JVM runs it anywhere, and the just-in-time (JIT) compiler turns hot code into machine code, often matching C++.
  • Java releases every six months since 2018; LTS versions are 11, 17, 21 and 25. Production code should stick to LTS and avoid preview features.
  • The chapter ends by busting myths: Java is not HTML, not JavaScript, not slow, not tied to browsers.

1.1 Java as a programming platform

  • The first edition (Horstmann and Gary Cornell) called Java a good language that was probably too late to be great, because compatibility with existing code limits clean design.
    • Newer features are sometimes less elegant than the original ones for the same reason.
  • Java was never just a language. It is a platform with three parts:

  • Many languages give a pleasant syntax, or portability and garbage collection, but lack a library, so you write your own graphics, networking or database code.
  • Java offers all three together, which is what makes it hard to resist.

1.2 The Java "white paper" buzzwords

  • The original authors summarised their goals as 11 buzzwords. Horstmann adds a verdict on each.
  • Sources: the white paper at https://www.oracle.com/java/technologies/language-environment.html and a shorter overview at https://horstmann.com/corejava/java-an-overview/7Gosling.pdf.
Buzzword Original claim Horstmann's verdict
Simple A cleaned-up C++ with no header files, pointer arithmetic, unions or operator overloading True of the syntax; the early runtime was tiny (about 40K interpreter plus 175K libraries), the library is now huge; tooling is now ahead of most languages
Object-oriented Focus on data and its interfaces, like C++ but with interfaces instead of multiple inheritance Java also has richer runtime introspection than C++ (see ch. 5)
Distributed Library support for TCP/IP, HTTP, FTP; open objects by URL like local files Taken for granted now; in 1995 it was a major undertaking in C++ or Visual Basic
Robust Early compile-time checks, runtime checks, no pointer model that can overwrite memory Biggest difference from C/C++; no more hours chasing pointer bugs
Secure Sandbox for downloaded code; no stack overruns, no memory access outside the process, no file access without permission Complex model; Princeton researchers found bugs soon after release; browsers dropped trust in Java
Architecture-neutral Bytecode independent of any CPU Virtual machines are older than Java (Lisp, Smalltalk, Pascal); bytecode can also be verified for safety
Portable No implementation-dependent behaviour: an int is always 32 bits, fixed byte order, Unicode strings True for libraries; user interface portability remains hard
Interpreted Rapid, exploratory development Not true for Java's first 20 years; jshell arrived in Java 9
High-performance Bytecode can be translated to machine code on the fly JIT compilers now compete with traditional compilers and can win
Multithreaded Better responsiveness and real-time behaviour First mainstream language with concurrency; motivated by web waits, now by multicore
Dynamic Libraries evolve without breaking clients; runtime type information is easy Lets code be added to a running program

Security in more detail

  • Original attitude to downloaded code was to run it in a sandbox and trust that it could never escape.
  • Over time hackers found subtle flaws, and Sun then Oracle struggled to keep up with fixes.
    • Remote code had to be digitally signed for a while; browsers eventually stopped trusting Java.
  • Hindsight verdict: the model was ahead of its time compared with Microsoft's ActiveX, which relied on digital signatures alone, and signed programs from famous vendors still crash and do damage.

Why the JIT matters

  • A JIT compiler sees which code runs often and optimises only that.
  • It can inline a method call when, given the classes currently loaded, no override exists, and can undo the optimisation later if a new class changes that.
    • This runtime knowledge is how Java can beat ahead-of-time compilers in some cases.

Concurrency, then and now

  • At release, multicore machines were exotic; threads were needed so the user interface did not freeze while waiting for a server.
  • Today concurrency matters because Moore's law has ended: we get more processors, not faster ones, and must keep them busy.
  • Horstmann: concurrent programming is never easy, but Java has made it manageable (ch. 10).

1.3 Java applets and the Internet

  • An applet was a Java program embedded in a web page like an image; the browser downloaded and ran its bytecode, so users never installed software and always got the latest version.
    • Example in the book: the Jmol applet, where you rotate and zoom molecule structures with the mouse (Figure 1.1).
    • At the time, plain web pages had only rudimentary JavaScript and no HTML canvas, so this was impressive.
  • Many people think applets drove Java's early popularity, but frustration followed:
    • different browsers shipped different, often very old, Java versions
    • Adobe Flash took over dynamic web effects
    • serious security issues led browsers to drop applet support altogether (and Flash fared no better)

1.4 A short history of Java

  • Based mainly on a July 1995 SunWorld interview with the creators.
  • 1991: Sun engineers led by Patrick Naughton and James Gosling wanted a small language for consumer devices such as cable TV boxes.
    • Needs: small, tight code, and not tied to one CPU. That led to a portable language compiling to a virtual machine.
    • Based on C++ rather than Lisp, Smalltalk or Pascal, because the team had a UNIX background. Gosling: the language was a tool, not the end.
    • Project code name Green; the language was first called Oak (after a tree outside Gosling's window), renamed Java when Oak turned out to be taken.
  • 1992: first product, an intelligent remote control called *7; nobody at Sun wanted to make it.
  • 1993 to mid-1994:
    • the group (renamed First Person, Inc.) tried to sell the technology, even bidding on a cable TV box (lost to a company led by Jim Clark, who then started Netscape)
    • Naughton claims 300,000 air miles of selling
    • First Person was dissolved in 1994.
  • Mid-1994: with the web growing, the team realised a browser needed exactly their ideas (architecture-neutral, reliable, secure) and built one.
    • Naughton and Jonathan Payne built HotJava, shown at SunWorld on 23 May 1995, which started the Java craze.
    • Mosaic, the browser of the day, came from the University of Illinois in 1993; Marc Andreessen worked on it as a student for $6.85 an hour before co-founding Netscape.

Versions

  • Java 1.0 (1996): not ready for serious work; you could not even print. 1.1 fixed obvious gaps, improved reflection and added a new GUI event model.
  • Java 1.2 (December 1998): scalable GUI and graphics replaced toy ones; three days after release Sun renamed it Java 2 Standard Edition SDK 1.2.
    • Two other editions appeared: Micro Edition (embedded devices) and Enterprise Edition (server side). The book covers Standard Edition.
  • 1.3 and 1.4: incremental. Hype for applets and client apps faded, and Java became the platform of choice for server-side applications.
  • Java 5.0 (2004): first significant language update since 1.1 (numbered 1.5 until the 2004 JavaOne conference).
    • Generics (like C++ templates, added without changing the virtual machine), plus for each, autoboxing and annotations inspired by C#.
  • Java 6 (2006): no language changes, performance and library improvements.
  • Java 7 (2011): released by Oracle after buying Sun in 2009; development had stalled in between.
  • Java 8 (2014): the biggest language change in almost two decades, a functional style that makes concurrent computation easy to express.
  • Java 9:
    • modules, an idea from 2008 by Mark Reinhold (chief engineer of the platform). It took eleven years to design a fit for the platform
    • whether it fits applications and libraries remains open.
  • From 2018: a release every six months so preview features arrive faster, sometimes across several rounds.
    • Example: pattern matching for switch was previewed four times from Java 17 and finalised in Java 21.
  • LTS (long-term support) versions get bug fixes and security updates for years. Production guidance: stay on LTS, avoid previews. LTS so far: 11, 17, 21, 25.

1.5 Common misconceptions about Java

Myth Reality
Java extends HTML Java is a programming language; HTML describes page structure. Only old HTML extensions placed applets in pages.
I use XML, so I do not need Java XML describes data; any language can process it, and Java has excellent XML support and many XML tools (Volume II).
Java is easy to learn Toy programs are easy, serious work is not. Only seven chapters of the book cover the language; the rest is the libraries, thousands of classes and tens of thousands of methods.
Java will be the universal language Entrenched elsewhere: Swift on iOS, JavaScript in the browser, C++ or C# on Windows. Java's edge is server-side and cross-platform clients.
Java is just another language Success comes from the support system (libraries, tools, integration) more than syntax: C++ and Visual Basic succeeded despite flaws.
Java is proprietary Sun released it under the GPL in 2007; Oracle committed to keeping it open; several open implementations exist.
Java is interpreted, so too slow Hot spots run as fast as C++ and sometimes faster thanks to the JIT.
Java runs inside web pages Not any more; most Java runs on servers producing pages or business logic.
Java is a major security risk Early exploits, slow responses and a now-deprecated security manager (the applet mechanism), but today Java is no less secure than other applications and far safer than C or C++.
JavaScript is a simpler Java Unrelated except for syntax; originally named LiveScript by Netscape. Java is strongly typed, so the compiler catches type errors that JavaScript finds only at run time.
Java replaces my PC with a cheap appliance Network computers failed; today phones and tablets dominate, mostly on Android, which is based on Java.

Summary points

  • Language, library and runtime together define Java; the runtime provides security, portability and garbage collection.
  • Bytecode plus a JVM per platform gives portability; the JIT gives speed.
  • The sandbox and applet story failed; server-side use succeeded.
  • Evolution is steady: generics (5), lambdas (8), modules (9), records and sealed classes (17), virtual threads (21), with an LTS version every few releases.
Terms to carry forward
  • Bytecode: architecture-neutral instructions produced by the compiler.
  • JVM: the virtual machine that runs bytecode on each platform.
  • JIT (just-in-time) compiler: translates frequently run bytecode to machine code at run time.
  • Applet: Java program embedded in a web page, now obsolete.
  • Sandbox: restricted environment for untrusted code.
  • LTS: long-term-support release (11, 17, 21, 25).
  • Preview feature: a feature shipped for feedback, possibly over several releases, before being finalised.
  • Moore's law: the rate of processor speed-up that ended, which is why concurrency matters now.
