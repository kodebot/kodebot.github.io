Core Java 11: Annotations

Source: Cay S. Horstmann, Core Java, Volume I: Fundamentals, 14th ed. (Pearson, 2025), ch. 11. Previous: Core Java 10: Concurrency. Next: Core Java 12: The Java Platform Module System.

Takeaways
  • An annotation is a tag that a tool processes; it never changes how the compiler generates VM instructions.
  • Annotations carry elements (compile-time constants, never null). They can mark declarations or type uses.
  • You define one with @interface. @Target says where it may appear, @Retention (SOURCE, CLASS, RUNTIME) says how long it lives.
  • Three processing styles: runtime reflection, source-level annotation processors (generate new files only), and bytecode engineering (class file API, load-time agents).
  • Building annotation tools is complex; most developers only need to understand how the tools they use work.

11.1 Using annotations

  • Annotations are tags inserted into source that a tool processes at source level or from class files
    • Examples: JUnit (https://junit.org) marks test methods, Jakarta Persistence (https://jakarta.ee/specifications/persistence/) maps classes to tables.
  • JCommander (https://jcommander.org) and picocli (https://picocli.info) use annotations to process command-line arguments.
  • An annotation is used like a modifier, with a leading @. @Test void checkRandomInsertions() does nothing alone; JUnit finds and calls the annotated methods.

11.1.1 Annotation elements

  • Elements are key/value pairs: @RepeatedTest(value=10, failureThreshold=3). Each annotation defines its element names and types.
  • An element value is one of:
    • a primitive value, a String, a Class object, an enum instance;
    • another annotation;
    • an array of those (not an array of arrays).
// BugReport usage
@BugReport(showStopper=true,
    assignedTo="Harry",
    testCase=CacheTest.class,
    status=BugReport.Status.CONFIRMED,
    ref=@Reference(id=11235811),
    reportedBy={"Harry", "Fred"})
  • Values must be compile-time constants and can never be null.
  • A single-element array can drop the braces: @BugReport(reportedBy="Harry").
  • Elements may have defaults: failureThreshold of @RepeatedTest defaults to Integer.MAX_VALUE.
  • If the only element is named value, drop value=: @RepeatedTest(10).

11.1.2 Multiple and repeated annotations

  • An item can carry several annotations (@Test @Tag("localized")).
  • A repeatable annotation may appear several times: @Tag("localized") @Tag("showstopper").

11.1.3 Annotating declarations

  • Two categories: declarations and type uses. Declaration annotations apply to:
    • classes (including enum), interfaces (including annotation interfaces);
    • methods, constructors;
    • fields (including enum constants and record components);
    • local variables (including for and try-with-resources), parameters and catch parameters;
    • type parameters, packages and modules.
  • Placement: before the class, interface or module keyword and its modifiers; before the type for variables.
// Placement examples
@Entity public class User { }

@SuppressWarnings("unchecked") List<User> users = null;

public User getUser(@Param("id") String userId)

public record Rectangle(@ToString(includeName=false) Point topLeft,
    int width, int height) { }

public class Cache<@NonNull V> { }
  • A package is annotated in package-info.java, which holds only the package statement preceded by annotations. The annotation's import comes after the package declaration.
// package-info.java
/**
 * Package-level documentation
 */
@Generated("com.horstmann.generator")
package com.horstmann.corejava.generated;

import javax.annotation.processing.Generated;
  • Annotations on local variables and packages are discarded at compile time, so they work only at source level.

11.1.4 Annotating type uses

  • A declaration annotation tells you about the item declared (@NonNull String userId)
    • @NonNull and @Localized belong to the Checker Framework (https://types.cs.washington.edu/checker-framework), which a static analysis tool uses to check the assertions.
  • To say "a list of non-null strings", use a type use annotation: List<@NonNull String>.
  • Where type uses can go:
Position Example
Generic type arguments List<@NonNull String>, Comparator.<@NonNull String> reverseOrder()
Before array brackets String[] @NonNull [] words (the arrays words[i] are non-null); String @NonNull [][] words (the variable is non-null); @NonNull String[][] words (the elements are non-null)
Superclasses and interfaces class Warning extends @Localized Message
Constructor calls new @Localized String(...)
Nested types Map.@Localized Entry
Casts and instanceof (@Localized String) text, text instanceof @Localized String (no effect on behaviour)
throws throws @Localized IOException
Wildcards and bounds List<@Localized ? extends Message>, List<? extends @Localized Message>
Method references @Localized Message::getText
  • Not annotatable: class literals (@NonNull String.class) and imports (import java.lang.@NonNull String;).
  • Convention: declaration annotations before modifiers, type use annotations after them. If an annotation is valid for both a variable and a type use, both are annotated.
// Convention
private @NonNull String text; // type use
@Id private String userId;    // variable

11.1.5 Receiver parameters

  • To say a method does not mutate this, you need to annotate this, which is never declared
    • The rare receiver parameter syntax declares it: the first parameter, named this, typed as the class.
// Point.java
public class Point
{
    public boolean equals(@NonNull Point this, @Nullable Object other)
    {
        return false;
    }
}
  • Methods only, not constructors (the object is not of the type until the constructor completes; a constructor annotation describes the constructed object).
  • An inner-class constructor has a hidden parameter for the enclosing instance. Name it EnclosingClass.this:
// Sequence.java
static class Sequence
{
    private int from;
    private int to;

    class Iterator implements java.util.Iterator<Integer>
    {
        private int current;

        public Iterator(@NonNull Sequence Sequence.this)
        {
            this.current = Sequence.this.from;
        }
    }
}

11.2 Defining annotations

  • Each annotation is declared by an annotation interface (@interface). Its methods are the elements.
// RepeatedTest.java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RepeatedTest
{
    int failureThreshold();
}
  • @interface creates a real Java interface. Tools get proxy objects implementing it and call methods such as failureThreshold().
  • Element methods have no parameters, no throws, and cannot be generic.
  • @Target and @Retention are meta-annotations
    • @Target takes an array of ElementType: @Target({ElementType.FIELD, ElementType.RECORD_COMPONENT, ElementType.TYPE})
    • Misplacing the annotation is a compile error.
  • Without @Target an annotation fits any declaration but not type parameters or type uses.
ElementType Applies to
ANNOTATION_TYPE Annotation type declarations
MODULE Modules
PACKAGE Packages
TYPE Classes (including enum) and interfaces (including annotation types)
METHOD Methods
CONSTRUCTOR Constructors
FIELD Fields (including enum constants)
PARAMETER Method or constructor parameters
RECORD_COMPONENT Record components
LOCAL_VARIABLE Local variables
TYPE_PARAMETER Type parameters
TYPE_USE Uses of a type
  • On a record component, the annotation passes to the fields and methods it produces, where permitted (the topLeft field gets it if the target includes FIELD).
  • @Retention:
Policy Behaviour
SOURCE Available to source processors, not in class files
CLASS In class files, not loaded by the VM (the default)
RUNTIME Available at runtime through reflection

  • Defaults use a default clause:
// BugReport.java
public @interface BugReport
{
    String[] reportedBy() default {};          // empty array
    Reference ref() default @Reference(id=0);  // default annotation
}
  • Defaults are computed dynamically, not stored in the annotation: change a default, recompile the annotation, and even older class files use the new one.
  • Every annotation interface extends java.lang.annotation.Annotation (a regular interface). You cannot extend annotation interfaces or implement them
    • tools and the VM generate proxies.
Annotation method Purpose
Class<? extends Annotation> annotationType() The annotation interface (not getClass(), which gives the proxy)
boolean equals(Object) Same interface and all elements equal
int hashCode() Compatible with equals, from the interface name and element values
String toString() Interface name plus element names and values

11.3 Annotations in the Java API

  • Defined in java.lang, java.lang.annotation and javax.annotation: four are meta-annotations, the rest are normal annotations.
Annotation Applies to Purpose
Override Methods Checks the method overrides a superclass method
Serial Methods Checks a serialisation method is correct
Deprecated All declarations Marks as deprecated
SuppressWarnings All except packages Suppresses warnings of a type
SafeVarargs Methods, constructors Asserts varargs use is safe
FunctionalInterface Interfaces Marks a single-abstract-method interface
Generated All declarations Marks tool-generated source

Retention Annotations Where it can be used
Documented Annotations Include in generated documentation

Repeatable Annotations May be applied several times

11.3.1 Annotations for compilation

  • @Deprecated:
    • the compiler warns on use
    • Same role as the @deprecated Javadoc tag, but it persists until runtime
    • The JDK's jdeprscan scans JAR files for deprecated elements.
  • @Override: public boolean equals(Point other) with @Override is a compile error because Object.equals takes an Object.
  • @Serial: checks the parameter types of serialisation methods that interfaces do not declare.
  • @SuppressWarnings("unchecked") on a declaration such as T[] result = (T[]) Array.newInstance(cl, n);.
  • @SafeVarargs: the method does not corrupt its varargs parameter (chapter 8).
  • @Generated
    • (for code generators): needs a unique generator id
    • an ISO 8601/RFC 3339 date and a comment are optional. Editors can hide generated code, generators can remove older output.
// Generated usage
@Generated(value="com.horstmann.generator", date="2025-12-04T12:08:56.235-0700")
  • @FunctionalInterface
    • (chapter 6) marks lambda conversion targets
    • adding a second abstract method becomes a compile error. Apply it only to interfaces that describe functions (not, say, AutoCloseable).
// IntFunction.java
@FunctionalInterface
public interface IntFunction<R>
{
    R apply(int value);
}

11.3.2 Meta-annotations

  • @Documented: treat the annotation like a modifier (private, static) in Javadoc. @SuppressWarnings is not documented (implementation detail); @FunctionalInterface is.
  • @Inherited: class annotations only. Subclasses automatically carry it, similar to marker interfaces such as Serializable.
// Persistent.java
@Inherited
@interface Persistent
{
}

@Persistent
class Employee
{
}

class Manager extends Employee // also @Persistent
{
}
  • @Repeatable: needs a container annotation holding an array. Two or more @Tag annotations are wrapped automatically into @Tags, which complicates processing.
// Tag.java
@Repeatable(Tag.class)
@interface Tag
{
    String value();
}

@interface Tags
{
    Tag[] value();
}

[!note] Book detail The book writes @Repeatable(Tag.class) on Tag itself. Taken literally the container should be named: @Repeatable(Tags.class) on Tag (unverified against the printed text).

11.4 Processing annotations at runtime

  • Goal: a customisable toString. For Point, show [5,10] rather than Point[x=5,y=10].
  • Annotate classes and the fields to include.
// ToString.java
@Target({ElementType.FIELD, ElementType.RECORD_COMPONENT, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface ToString
{
    boolean includeName() default true;
}

// Point.java
@ToString(includeName=false)
public class Point
{
    @ToString(includeName=false) private int x;
    @ToString(includeName=false) private int y;
}

// Rectangle.java
@ToString
public record Rectangle(
    @ToString(includeName=false) Point topLeft,
    @ToString int width,
    @ToString int height)
{
}
  • The intended output is Rectangle[[5, 10],width=20,height=30].
  • You cannot replace toString at runtime, so provide a method that formats any object and uses the annotations when present.
  • The key API, from AnnotatedElement (implemented by Class, Field, Parameter, Method, Constructor, Package): getAnnotation, getDeclaredAnnotation, getAnnotationsByType, getDeclaredAnnotationsByType, getAnnotations, getDeclaredAnnotations, isAnnotationPresent.
    • Methods with Declared give only annotations on the item itself; the others include inherited ones (@Inherited on a superclass).
    • getAnnotation(ToString.class) returns a proxy object, or null if absent.
    • For a repeatable annotation that was repeated, getAnnotation returns null (the repeats are in the container)
      • Use getAnnotationsByType, which looks through the container (a single use gives an array of length 1).
    • getAnnotations returns all annotations, repeats wrapped in containers.
  • Listing 11.2 (ToStrings):
    • null gives "null"
    • a class without @ToString uses its normal toString (the recursion stops there)
    • otherwise it loops over getDeclaredFields, includes fields annotated with @ToString, calls setAccessible(true), optionally prints the name, and recurses on the value.
  • Listing 11.1 (RuntimeAnnotationDemo) builds new Rectangle(new Point(5, 10), 20, 30) and prints ToStrings.toString(rect).
// ToStrings.java (core)
public static String toString(Object obj)
{
    if (obj == null)
        return "null";
    Class<?> cl = obj.getClass();
    ToString ts = cl.getAnnotation(ToString.class);
    if (ts == null)
        return obj.toString();
    var result = new StringBuilder();
    if (ts.includeName())
        result.append(cl.getName());
    result.append("[");
    boolean first = true;
    for (Field f : cl.getDeclaredFields())
    {
        ts = f.getAnnotation(ToString.class);
        if (ts != null)
        {
            if (first)
                first = false;
            else
                result.append(",");
            f.setAccessible(true);
            if (ts.includeName())
            {
                result.append(f.getName());
                result.append("=");
            }
            try
            {
                result.append(ToStrings.toString(f.get(obj)));
            }
            catch (ReflectiveOperationException ex)
            {
                ex.printStackTrace();
            }
        }
    }
    result.append("]");
    return result.toString();
}

  • The typical recipe: reflect to find classes and fields, call getAnnotation or getAnnotationsByType, then call the annotation interface's methods for the element values.
AnnotatedElement method Purpose
isAnnotationPresent(Class) Whether an annotation of that type is present
getAnnotation(Class<T>) The annotation or null
getAnnotationsByType(Class<T>) (8) All of a repeatable type; empty array if none
getAnnotations() All, including inherited; empty array if none
getDeclaredAnnotations() All declared, excluding inherited

11.5 Source-level annotation processing

  • Annotations can drive source generation. The example regenerates toString as real Java source, so it compiles with the program and runs at full speed without reflection.

11.5.1 Annotation processors

  • Processing is part of the compiler: javac -processor ProcessorClassName1,ProcessorClassName2 sourceFiles.
  • Each processor runs in turn with the annotations it is interested in
    • If one creates a new source file, another round follows
    • When a round yields no new files, everything is compiled.
  • A processor can only generate new files, never modify existing ones.
  • It implements Processor, normally by extending AbstractProcessor, and declares what it supports; wildcards such as "com.horstmann.*" or "*" are allowed.
  • process(Set<? extends TypeElement> annotations, RoundEnvironment currentRound) is called once per round.
// ToStringAnnotationProcessor.java (outline)
@SupportedAnnotationTypes("annotations.ToString")
@SupportedSourceVersion(SourceVersion.RELEASE_8)
public class ToStringAnnotationProcessor extends AbstractProcessor
{
    public boolean process(Set<? extends TypeElement> annotations,
        RoundEnvironment currentRound)
    {
        return true;
    }
}

11.5.2 The language model API

  • Use it for source-level analysis. Unlike reflection (VM view of classes), it analyses a program by the rules of the language.
  • The compiler builds a tree of javax.lang.model.element.Element nodes: TypeElement, VariableElement, ExecutableElement and so on (compile-time analogues of Class, Field/Parameter, Method/Constructor).
  • RoundEnvironment.getElementsAnnotatedWith(Class) returns the annotated elements; getElementsAnnotatedWithAny(Set) suits repeated annotations.
  • AnnotatedConstruct is the source-level AnnotatedElement, with getAnnotation and getAnnotationsByType.
  • TypeElement.getEnclosedElements() lists fields and methods. getSimpleName (on an Element) and getQualifiedName (on a TypeElement) give a Name, convertible with toString.

11.5.3 Using annotations to generate source code

  • A processor cannot add methods to existing classes, so the generated toString methods go into a utility class ToStrings with one overload per annotated class plus a fallback toString(Object) using Objects.toString.
  • No reflection is wanted, so accessor methods are annotated, not fields:
// Rectangle.java (annotated accessors)
@ToString
public class Rectangle
{
    @ToString(includeName=false) public Point getTopLeft() {
        return topLeft;
    }
    @ToString public int getWidth() {
        return width;
    }
    @ToString public int getHeight() {
        return height;
    }
}
  • The processor generates, for each annotated class:
// generated ToStrings.java (one method)
public static String toString(Rectangle obj)
{
    var result = new StringBuilder();
    result.append("Rectangle");
    result.append("[");
    result.append(toString(obj.getTopLeft()));
    result.append(",");
    result.append("width=");
    result.append(toString(obj.getWidth()));
    result.append(",");
    result.append("height=");
    result.append(toString(obj.getHeight()));
    result.append("]");
    return result.toString();
}
  • process (Listing 11.4):
    • returns at once if annotations is empty (later rounds are called with an empty set, so the file is not created twice);
    • creates ToStrings via processingEnv.getFiler().createSourceFile(...);
    • writes the package and class header, one method per TypeElement found by getElementsAnnotatedWith(ToString.class), then toString(Object);
    • reports IOException through processingEnv.getMessager() with Diagnostic.Kind.ERROR.
  • writeToStringMethod: reads the qualified class name, prints the header and StringBuilder, adds the class name if includeName, then for each enclosed element with @ToString appends the field name (derived from the accessor with Introspector.decapitalize after stripping get or is, so getWidth gives width, getURL gives URL) and toString(obj.methodName()).
  • -XprintRounds shows the rounds: round 1 has the input files and the ToString annotation, round 2 has no input files and is the last round.
$ javac v1ch11/sourceAnnotations/ToStringAnnotationProcessor.java
$ javac -XprintRounds -processor v1ch11.sourceAnnotations.ToStringAnnotationProcessor \
    v1ch11/annotated/*.java
$ java v1ch11/sourceAnnotations/SourceLevelAnnotationDemo.java

Round 1:
  input files: {v1ch11.annotated.Point, v1ch11.annotated.Rectangle}
  annotations: [v1ch11.sourceAnnotations.ToString]
  last round: false
Round 2:
  input files: {}
  annotations: []
  last round: true

  • Processors may generate any file type: XML descriptors, property files, scripts, HTML documentation.
  • Getters and setters
    • from @Property private String title; would need editing the same class, which processors cannot do
    • An annotation describes an item, it is not a directive to change code.
  • Project Lombok works around this by modifying internal compiler data structures, so it generates getters and setters; it works for now but is not standard Java.

11.6 Bytecode engineering

  • Annotations stay in class files unless removed, so a third route is processing at bytecode level
    • The class file format is documented at https://docs.oracle.com/javase/specs/jvms/se21/html
    • It is complex, but since Java 24 the JDK has a class file API (https://openjdk.org/jeps/484).

11.6.1 Modifying class files

  • Example: @LogEntry(logger=loggerName) on a method makes the tool insert, at the start of the method, the equivalent of System.getLogger(loggerName).log(System.Logger.Level.TRACE, "Entering {0}.{1}", className, methodName).
  • Steps:
    1. Load the class file bytes.
    2. Locate all methods.
    3. For each, check for LogEntry.
    4. If present, insert the bytecodes at the start.
  • The inserted instructions (book list): ldc loggerName, invokestatic System.getLogger(String), getstatic System.Logger.Level.INFO, ldc "Entering {0}.{1}", iconst_2, anewarray, dup, iconst_0, ldc className, aastore, dup, iconst_1, ldc methodName, aastore, invokeinterface System.Logger.log(...).
  • Result for @LogEntry(logger="com.horstmann") public int hashCode() in Item:
Dec 03, 2025 5:58:44 PM set.Item hashCode
INFO: Entering set.Item.hashCode
  • Run it:
$ javac v1ch11/set/Item.java v1ch11/set/SetDemo.java
$ javac v1ch11/bytecodeAnnotations/EntryLogger.java
$ java v1ch11.bytecodeAnnotations.EntryLogger v1ch11/set/Item.class
$ java v1ch11.set.SetDemo
  • javap -c set.Item before and after shows the instructions at the beginning of hashCode, equals and compareTo. Constant pool indices may differ on your machine.
  • SetDemo (Listing 11.7) sets the com.horstmann logger and a ConsoleHandler to FINEST, then adds Toaster 1279, Microwave 4104, Toaster 1279 to a HashSet<Item>
    • Output shows three hashCode messages and one equals call (the duplicate), then [[description=Microwave, partNumber=4104], [description=Toaster, partNumber=1279]].
  • The point: annotations add directives; a bytecode tool reads them and changes the VM instructions.
  • EntryLogger (Listing 11.5), in short:
    • ClassFile.of().parse(bytes) gives a ClassModel; the class name comes from thisClass().asInternalName() with / replaced by ..
    • A MethodTransform rebuilds a method's CodeModel with withCode, first calling addLoggingCode, then copying the original elements.
    • ClassTransform.transformingMethods(EntryLogger::hasLoggingAnnotation, methodTransform) applies it only to methods with the annotation.
    • hasLoggingAnnotation and getLoggerName read the RuntimeVisibleAnnotations attribute and compare the annotation descriptor with LogEntry's
      • logger is read as an AnnotationValue.OfString.
    • addLoggingCode uses CodeBuilder calls (ldc, invokestatic, getstatic, anewarray, aastore, invokeinterface).
    • main reads the class file, calls addLogging and writes the bytes back.

11.6.2 Modifying bytecodes at load time

  • Another tool in the build is cumbersome, so defer to load time, when the class loader loads the class.
  • The instrumentation API has a hook for a bytecode transformer, which must be installed before main
    • Do that with an agent: a library loaded to monitor a program, which initialises in premain.
  • Building an agent:
    1. Implement public static void premain(String arg, Instrumentation instr). It gets one command-line argument and the Instrumentation to install hooks.
    2. Write a manifest EntryLoggingAgent.mf with Premain-Class: v1ch11.bytecodeAnnotations.EntryLoggingAgent.
    3. Package it into a JAR.
    4. Launch with java -javaagent:AgentJARFile=agentArgument ....
$ javac v1ch11/bytecodeAnnotations/EntryLoggingAgent.java
$ jar cvfm EntryLoggingAgent.jar v1ch11/bytecodeAnnotations/EntryLoggingAgent.mf \
    v1ch11/bytecodeAnnotations/Entry*.class
$ javac v1ch11/set/*.java
  • The book then runs SetDemo with -javaagent:...= and the class name Item as the agent argument (the exact command line is cut off in the captured text).
  • Listing 11.8:
    • the agent registers a ClassFileTransformer
    • It compares the class name (/ to .) with the agent argument; on a match it returns EntryLogger.addLogging(data), otherwise null
    • The modified bytes are not saved: they are returned for loading
    • This is "just in time" bytecode modification.
// EntryLoggingAgent.java
public class EntryLoggingAgent
{
    public static void premain(final String arg, Instrumentation instr)
    {
        instr.addTransformer(new ClassFileTransformer()
        {
            public byte[] transform(ClassLoader loader, String className, Class<?> cl,
                ProtectionDomain pd, byte[] data) throws IllegalClassFormatException
            {
                if (!className.replace("/", ".").equals(arg))
                    return null;
                return EntryLogger.addLogging(data);
            }
        });
    }
}

Summary points

  • You learned to add annotations, design annotation interfaces and implement tools that use them.
  • Three processing technologies:
    • scripting, compiling Java programs and processing annotations. The first two are straightforward
    • annotation tools are complex and rarely needed by most developers, but this chapter explains how the tools you meet work.
  • Next, chapter 12 covers the Java Platform Module System, which protects the integrity of the platform.
Terms to carry forward
  • Annotation element: a key/value pair, a method of the annotation interface.
  • Meta-annotation: @Target, @Retention, @Documented, @Inherited, @Repeatable.
  • Type use annotation: annotates a type occurrence such as List<@NonNull String>.
  • Receiver parameter: explicit this first parameter, to annotate the receiver.
  • Retention policy: SOURCE, CLASS (default), RUNTIME.
  • Annotation processor / round: compiler plug-in that generates new files; repeats until no new sources.
  • Language model API: compile-time view of the program (Element, TypeElement).
  • Class file API / agent: Java 24 library to edit class files; premain plus Instrumentation for load-time edits.
