Core Java 13: Appendix, Java Keywords

Source: Cay S. Horstmann, Core Java, Volume I: Fundamentals, 14th ed. (Pearson, 2025), appendix. Previous: Core Java 12: The Java Platform Module System.

Takeaways
  • The appendix lists every keyword and keyword-like word, with its meaning, its kind and the chapter that covers it.
  • Four kinds: keyword, restricted keyword (only meaningful in a module declaration), restricted identifier (an identifier except in certain positions) and literal (null, true, false are not keywords).
  • const and goto are reserved but unused.
  • var is always an identifier unless it appears where a type is expected.

The four kinds

  • A restricted keyword is a keyword only in a module declaration, otherwise an identifier (chapter 12).
  • A restricted identifier is an identifier unless used in certain positions. Example: var is an identifier unless it is used where a type is expected.
  • null, false and true are literals, not keywords.

Remarks on the printed table
  • The chapter column gives synchronized and volatile as chapter 12, but both are covered in chapter 10 (concurrency) in this edition; the page itself does not explain the mismatch (unverified which is intended).
  • when appears among the restricted keywords in the table although it is a pattern-guard word, not a module word.
  • provides is printed with the same description as uses; the module chapter explains provides ... with as offering an implementation.

Summary points

  • 50-odd keywords, two of them unused (const, goto); strictfp is obsolete.
  • Module words (exports, opens, requires and so on) are only special inside module-info.java.
  • var, record, sealed, permits, yield are identifiers outside their positions; null, true, false are literals.
Terms to carry forward
  • Keyword: always reserved (class, static).
  • Restricted keyword: reserved only in module declarations (exports, opens).
  • Restricted identifier: contextual (var, record, sealed, yield).
  • Literal: null, true, false.
