Fundamentals of Software Architecture 0: Preface

Source: Mark Richards and Neal Ford, Fundamentals of Software Architecture, 2nd ed. (O'Reilly, 2025), Preface. Next: Fundamentals of Software Architecture 1: Introduction.

Takeaways
  • The second edition grew well beyond the first: more consistent style chapters, new sections per style, and five new chapters.
  • The book treats architecture as an engineering discipline (repeatable, rigorous, measurable), not a craft of one-off works.
  • Its stance: everything is a trade-off, so it analyses trade-offs instead of passing value judgments on technologies.
  • Architects must question inherited axioms because the software ecosystem keeps changing.
  • It will not make anyone an architect overnight; it gives a modern overview from structure to soft skills.

0.1 What is new in the second edition

  • Styles chapters are more consistent, so they compare better.
  • The star ratings gained sections and a few new categories.
  • Each architecture style gained new sections on:
    • cloud considerations
    • data topologies
    • team topologies
    • governance
  • Major additions to popular chapters, such as Chapters 15 (event-driven) and 18 (microservices).
  • Entirely new chapters:
    • Chapter 11: the modular monolith style
    • Chapter 20: architectural patterns
    • Chapter 26: architectural intersections
    • Chapter 27: the laws of software architecture, revisited (a new corollary and a new law)

0.2 Why the axioms keep moving

Mathematicians build theories on axioms: statements accepted as self-evidently true. Software architects build theories on axioms too, but software is "softer", so the axioms themselves change.

The ecosystem sits in dynamic equilibrium: balanced at any moment, changing over the long term. The authors' example is containerisation: Kubernetes did not exist a decade earlier, yet whole conferences now serve its users.

  • One small change causes another; repeated hundreds of times they produce a new ecosystem.
  • Architects therefore have a responsibility to question assumptions left over from earlier eras.
  • Many architecture books were written in an era that barely resembles today's.

The authors trace an evolution of capabilities, each step adding new trade-offs:

  • For many years the tongue-in-cheek definition of architecture was "the stuff that's hard to change later".
  • Then the microservices style appeared, where change is a first-class design consideration.

0.3 An engineering approach

The subtitle is A Modern Engineering Approach. Developers have long wished to move software from a craft (skilled artisans, one-off works) to an engineering discipline (repeatability, rigour, effective analysis).

  • Software engineering still lags other disciplines by many orders of magnitude; software is a very young discipline.
  • Architects have made big improvements, and modern Agile engineering practices allowed great strides in the systems they design.

0.4 Trade-off analysis over technology love

  • Developers easily become enamoured with a particular technology or approach.
  • Architects must soberly assess "the good, bad, and ugly" of every choice.
  • Almost nothing offers a convenient binary choice: everything is a trade-off.
  • So the book eliminates value judgments about technology and teaches trade-off analysis instead.

0.5 Scope

  • It will not make someone an architect overnight; the field is nuanced and has many facets.
  • It aims to give existing and aspiring architects a modern overview, from structure to soft skills.
  • It covers well-known patterns but leans on lessons learned, tools and engineering practices, and rethinks existing axioms against the current ecosystem.

Skipped as non-content: conventions, supplemental material, permissions, how to contact, and acknowledgments.

Summary points

  • The second edition adds consistency, new per-style sections and five new chapters.
  • Axioms in software change, so architects question them regularly.
  • Architecture is treated as engineering: repeatable, rigorous, measurable.
  • Every choice is a trade-off; the book analyses rather than judges.
Terms to carry forward
  • Axiom: a statement regarded as established or self-evidently true.
  • Dynamic equilibrium: balanced at any moment, yet changing over the long term.
  • Star ratings: the book's per-style scoring of architecture characteristics, extended in this edition.
