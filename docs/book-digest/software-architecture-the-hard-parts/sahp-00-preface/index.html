Software Architecture: The Hard Parts 0: Preface

Source: Neal Ford, Mark Richards, Pramod Sadalage and Zhamak Dehghani, Software Architecture: The Hard Parts (O'Reilly, 2021), preface. Next: Software Architecture: The Hard Parts 1: What Happens When There Are No "Best Practices"?.

Takeaways
  • The book grew from a pile of examples Neal Ford and Mark Richards set aside while writing Fundamentals of Software Architecture; each had "no easy solutions but rather a collection of messy trade-offs", so they called the pile "The Hard Parts".
  • They worked every example through trade-off analysis, and paid attention to the process they used to reach the trade-offs.
  • A key early finding was the growing importance of data in architecture decisions: who can and should access data, who can and should write it, and how to separate analytical and operational data.
  • Data experts (Pramod Sadalage and Zhamak Dehghani) joined so the book covers decisions from both angles: architecture to data and data to architecture.
  • The result: difficult modern architecture problems, the trade-offs that make them hard, and an illustrated guide to applying the same analysis to your own problems.
