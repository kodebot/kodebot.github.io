Appendices B to G: projects, HTTP, JSON, MySQL, tools, further reading

Source: Laurentiu Spilca, Spring Start Here, Second Edition (Manning, MEAP V05), appendices B to G. Appendix A (answers to chapter questions) is in Appendix A: Answers to the chapter questions. HTTP and JSON support chapters 7 to 10 (Ch 7: Understanding Spring Boot and Spring MVC, Ch 10: Implementing REST endpoints).

Appendix B: Working with the book's projects

  • The author uses IntelliJ IDEA, but any modern IDE opens and creates Maven or Gradle projects (Eclipse works too).
  • Open an existing project with Open; create one with New Project: choose a standard Java project, Maven or Gradle, a name, and Java 25 (the version used in the book).
  • You only need to know how to add dependencies in pom.xml (the <dependencies> tag, in the project root). Each example says which ones it needs. Minimal POM from the book:
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
   xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
   xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
     <modelVersion>4.0.0</modelVersion>
     <groupId>com.example</groupId>
     <artifactId>ssh_ch1_ex1</artifactId>
     <version>1.0-SNAPSHOT</version>
     <properties>
         <maven.compiler.source>25</maven.compiler.source>
         <maven.compiler.target>25</maven.compiler.target>
         <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
     </properties>
     <dependencies>
         <dependency>
             <groupId>org.springframework</groupId>
             <artifactId>spring-context</artifactId>
             <version>7.0.1</version>
         </dependency>
     </dependencies>
</project>
  • Advice: experiment, change things, see what happens; fixing problems is part of learning.

Appendix C: A quick introduction to HTTP

Why in a Spring book: most apps built with an application framework are web apps, and web apps use HTTP.

Definition (the book's visual): HTTP is a stateless, text-based, request-response protocol that uses the client-server model.

  • Stateless: requests are independent of one another.
  • Text-based: information is exchanged as plain text.

C.2 The request

  1. Request URI (mandatory): the resource the client wants, http://<server_location>:<application_port>/<resource_path>, e.g. http://www.manning.com/books/spring-start-here. The book's formula: URI = URL + path (the URL identifies server and app; adding the path to a resource makes it a URI). Many people use the terms interchangeably.
  2. Method (mandatory): a verb for the action on the resource.
  3. Parameters (optional): small data (roughly 10 to 50 characters) appended to the URI as a query expression; also called query parameters.
  4. Headers (optional): small data not visible in the URI.
  5. Body (optional): larger data (hundreds of characters or more).

Example (the book's old-style form submit):

POST /servlet/default.jsp HTTP/1.1
Accept: text/plain; text/html
Accept-Language: en-gb
Connection: Keep-Alive
Host: localhost
Referer: http://localhost/ch8/SendDetails.html
User-Agent: Mozilla/4.0 (MSIE 4.01;Windows 98)
Content-Length: 33
Content-Type: application/x-www-form-urlencoded
Accept-Encoding: gzip, deflate

lastName=Einstein&firstName=Albert

Methods:

  • The browser address bar always sends GET; submitting a form usually sends POST (the page developer chooses); a script (JavaScript) chooses its own.
  • Common: GET obtain data, POST add data, PUT change data, DELETE remove data.
  • Never misuse a method (e.g. a GET that changes data), even though HTTP cannot stop you: it hurts reliability, security and maintainability.
  • Less common but relevant: OPTIONS (ask which methods the server supports; most often used for CORS, cross-origin resource sharing; the author points to chapter 10 of Spring Security in Action, 2nd ed., https://livebook.manning.com/book/spring-security-in-action-second-edition/chapter-10) and PATCH (change part of a resource; PUT is for completely replacing a resource or adding it where it does not exist; developers still use PUT where PATCH would be right).
GET http://example.com/products                       # all products
DELETE http://example.com/products                    # remove all products
DELETE http://example.com/products?product=Beer       # remove one, named by a parameter

Send data via request parameters, headers or body; parameters and body are optional. Small individual values: parameters; more data: body.

C.3 The response

  • Status (mandatory, the only required part): integer 100 to 599, a short result code.
  • Headers (optional): key-value pairs, 10 to 50 characters.
  • Body (optional): larger data, even whole files.
HTTP/1.1 200 OK
Server: Microsoft-IIS/4.0
Date: Mon, 14 May 2012 13:13:33 GMT
Content-Type: text/html
Last-Modified: Mon, 14 May 2012 13:03:42 GMT
Content-Length: 112

<html>
<head><title>HTTP Response</title></head>
<body>Hello Albert!</body>
</html>
  • 2xx: processed correctly. 200 OK (most common), 201 Created (e.g. after a POST added a resource; optional detail), 204 No Content (do not expect a body).
  • 4xx:
    • the client did something wrong
    • 400 Bad Request (generic: validation, unreadable value), 401 Unauthorized (needs authentication), 403 Forbidden (not allowed), 404 Not Found.
  • 5xx: the server failed on a valid request, e.g. database unreachable. 500 Internal Server Error is the generic one.
  • 1xx and 3xx exist but are skipped. More: https://datatracker.ietf.org/doc/html/rfc7231

C.4 The HTTP session

Requests are independent, yet a shop cart must remember a client across requests. The server gives the client a unique session ID, ties it to a place in server memory, and the client sends the ID in a request header with every later request.

The session ends after idle time (configurable in the servlet container and the app; keep it to a few hours at most, usually under one hour, since long sessions eat memory). A request after the session ended starts a new session.

Appendix D: Using JSON formatting

JSON (JavaScript Object Notation) is the main format for data exchanged by REST endpoints. It represents object instances by their attributes.

  • An object is in curly braces { }. It has no name and no type; only attributes matter.
  • Attribute-value pairs, separated by commas; name and value separated by a colon.
  • Attribute names and string values in double quotes (escape inner quotes with a backslash \). Numbers have no quotes.
{
  "name": "chocolate",
  "price": 5
}

Nested objects (the same rules repeat, nest as deep as needed):

{
  "name" : "chocolate",
  "price" : 5,
  "pack" : { "color" : "blue" }
}

Collections use brackets with comma-separated items:

[
  { "name" : "chocolate", "price" : 5 },
  {
    "name": "candy",
    "price": 3
  }
]

Appendix E: Installing MySQL and creating a database

Needed for chapters 12 to 14. Any relational DBMS works (MySQL, Postgres, Oracle, MS SQL); the Java and Spring code is the same. The book picks MySQL: free, light, easy to install.

  1. Install the DBMS (MySQL): https://dev.mysql.com/downloads/mysql/ ; install guide https://dev.mysql.com/doc/refman/8.0/en/installing.html. You may need to create an account; remember the credentials.
  2. Install a client app: MySQL Workbench https://dev.mysql.com/downloads/workbench/ ; guide https://dev.mysql.com/doc/workbench/en/wb-installing.html.
  3. Connect the client to the local DBMS: click the plus next to "MySQL Connections", name the connection, enter the credentials, "Test Connection". If no credentials were set during installation, use user root with an empty password. A warning in some MySQL versions can be ignored ("Continue Anyway"). On success you see "Successfully made the MySQL connection".
  4. Create the database: double-click the connection, click the small cylinder icon in the toolbar, name the database, Apply, confirm Apply (the dialog shows the SQL it sends), and it appears on the left. (The book's screenshot names it "spring quickly"; chapter 12's URL uses spring_start_here.)

Appendix F: Recommended tools

  • IDEs:
    • JetBrains IntelliJ IDEA (the book's IDE; free Community edition opens the projects; Ultimate needs a license and adds Spring helpers, https://www.jetbrains.com/idea/)
    • Eclipse with Spring Tools (https://www.eclipse.org/downloads/)
    • Spring Tools Suite (https://spring.io/tools).
  • REST tools: Postman (GUI, also automation scripts and documentation, https://www.postman.com/); cURL (command line, https://curl.se/download.html).
  • MySQL: MySQL Server (https://dev.mysql.com/downloads/mysql/), MySQL Workbench (https://www.mysql.com/products/workbench/), alternative client SQLYog (https://webyog.com/product/sqlyog/).
  • PostgreSQL: an alternative DBMS (https://www.postgresql.org/download/) with pgAdmin to administer it (https://www.pgadmin.org/).

  • Spring in Action, 6th ed., Craig Walls (Manning, 2022): next book on Spring; refresher, then Spring Security, asynchronous communication, Project Reactor, RSocket, Boot actuator.

  • Spring Boot: Up and Running, Mark Heckler (O'Reilly, 2021): deep dive into Boot, which is used in over half the book's chapters.
  • Reactive Spring, Josh Long (self-published, 2020): reactive web apps, read after Spring in Action.
  • JUnit in Action, Cătălin Tudose (Manning, 2020): testing in depth.
  • Learning SQL, 3rd ed., Alan Beaulieu (O'Reilly, 2020): SQL refresher.
  • OCP Oracle Certified Professional Java SE 21 Developer Complete Study Guide, Jeanne Boyarsky and Scott Selikoff (Sybex, 2024): refresh Java fundamentals
    • (Chapter 12 cites the Java SE 17 edition, 2022, for JDBC.)
  • The author's YouTube channel, Spring Framework playlist: youtube.com/c/laurentiuspilca, http://mng.bz/yJQE.

Other books cited in chapters: API Design Patterns (Geewax, Manning 2021), Designing APIs with Swagger and OpenAPI (Ponelat and Rosenstock, Manning 2022), Cloud Native Spring in Action (Vitale, Manning 2022), Java Persistence with Spring Data and Hibernate (Tudose, Manning 2023), Spring Boot in Practice (Musib, Manning 2022).
