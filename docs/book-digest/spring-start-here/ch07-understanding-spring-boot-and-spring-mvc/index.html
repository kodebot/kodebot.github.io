Ch 7: Understanding Spring Boot and Spring MVC

Source: Laurentiu Spilca, Spring Start Here, Second Edition (Manning, MEAP V05), ch. 7. Previous: Ch 6: Using aspects with Spring AOP. Book project: ssh_ch7_ex1. First chapter of part 2 (implementation). Needs chapters 2 to 6; the book says to go back if you skipped them.

Takeaways
  • A web app has a client (browser) and a server (backend) talking over HTTP.
  • A Java backend needs a servlet container (Tomcat) to translate HTTP to Java.
  • Spring Boot removes the painful configuration with three things: a project generator (Initializr), dependency starters and autoconfiguration (convention over configuration).
  • Spring MVC is the request-handling design Boot sets up; you only write the controller.

7.1 What is a web app?

  • Any app you open in a browser. Compared with 1990s desktop apps: nothing to install, works on any device (tablet, phone).
  • Client side = frontend: what the user touches (the browser). Sends requests, receives responses.
  • Server side = backend: processes (and sometimes stores) data, then responds; may use a database or other services.
  • Concurrency matters: the backend serves many clients at once (computer, phone, tablet). Code that changes shared resources can hit race conditions (as in chapter 5).

7.1.2 Two ways to build a web app

  • No separation: the backend returns the finished view (HTML, CSS, images, scripts). The browser shows exactly what it gets. Mostly used for small apps; this is what the chapter builds.
  • Frontend-backend separation:
    • the backend returns raw data (JSON or XML)
    • A separate frontend app (Angular, React, Vue.js) in the browser decides how to display it
    • Seen as the modern way for larger apps: different teams work in parallel and deploy independently.

7.1.3 Servlet container

  • Browser and server talk HTTP (request-response: the client sends a request and waits for the answer). Appendix C of the book covers what you need (chapters 7 to 9).
  • You could handle HTTP yourself, but a servlet container (a.k.a. web server) already translates HTTP to a Java app and back
    • The book uses Tomcat
    • Alternatives: Jetty (https://www.eclipse.org/jetty/), JBoss (https://www.jboss.org/), Payara (https://www.payara.fish/)
    • The author recommends the We Are Developers Congress 2026 talk "Standing on the shoulders of servlets: the web of Java" (https://www.wearedevelopers.com/videos/2134-standing-on-the-shoulders-of-servlets-the-web-of-java) for the servlet details.
  • Servlet: a Java object that interacts directly with the container. On a request, the container calls the servlet's method, passing request and response objects.
  • Historically one servlet per URL path (/home/profile/edit) had to be written and registered by hand
    • The container keeps a context of servlets, like Spring's context of beans (hence "servlet container").
  • You will not write servlets. Spring defines one and registers it, making it the entry point into your app.

7.2 The magic of Spring Boot

Without Boot: configure a servlet container, create a servlet, wire it to every request. The author and his students hated this when he taught Spring Framework 3.

Spring Boot is a Spring ecosystem project for modern apps; it removes much configuration code, which helps most in SOA and microservices, where you create many apps. Its main features:

  • Simplified project creation: a generator gives you a configured skeleton.
  • Dependency starters: groups of dependencies for one purpose, with compatible versions.
  • Autoconfiguration based on dependencies: defaults for what you added; you only change what differs.

7.2.1 Project initialization (ssh_ch7_ex1)

Use Spring Initializr: built into IntelliJ Ultimate and Spring Tool Suite (not IntelliJ Community), or in the browser at https://start.spring.io. Steps:

Choices: build tool (Maven or Gradle), Java version, even Kotlin or Groovy. The book keeps Maven and Java 25. Add the Spring Web dependency; name the project.

What Initializr puts in the project:

  1. Main class:
    @SpringBootApplication
public class Main {
    public static void main(String[] args) {
      SpringApplication.run(Main.class, args);
    }
}
    The book does not explain what SpringApplication.run() or @SpringBootApplication do internally; it recommends Spring Boot in Practice (Somnath Musib, Manning, 2022) and Spring Boot: Up and Running (Mark Heckler, O'Reilly, 2021).
  2. Maven parent (Boot 4.0.4 in the book): its main job is to give you compatible versions of dependencies, so you normally omit versions.
    <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.0.4</version>
    <relativePath/>
</parent>
  3. Dependency (a starter, no version):
    <dependency>
   <groupId>org.springframework.boot</groupId>
   <artifactId>spring-boot-starter-webmvc</artifactId>
</dependency>
  4. Spring Boot Maven plugin (adds part of the default configuration):
    <build>
   <plugins>
      <plugin>
          <groupId>org.springframework.boot</groupId>
          <artifactId>spring-boot-maven-plugin</artifactId>
      </plugin>
   </plugins>
</build>
  5. application.properties in resources: empty for now; used later for configuration values.

7.2.2 Dependency starters

  • A starter is a capability-oriented group of compatible dependencies. Names start spring-boot-starter- plus the capability.
  • You ask for a capability (web, database, security), not for individual dependencies.
  • Your POM lists only spring-boot-starter-webmvc, yet "External Libraries" shows the Spring context, AOP, Tomcat and more, at compatible versions.

7.2.3 Autoconfiguration (convention over configuration)

Just start the app (you wrote nothing yet):

Tomcat started on port(s): 8080 (http) with context path ''
Started Main in 1.684 seconds (JVM running for 2.306)

Boot saw the web dependency, so it configured Tomcat (its convention for a servlet container) on port 8080. Convention = the most common way to configure something. You change only what your app needs differently.

7.3 A web page with Spring MVC

Starting Tomcat does not make a web app yet. Two steps: write an HTML document, write a controller action for it.

Step 1: resources/static/home.html (the default folder for pages):

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Home Page</title>
</head>
<body>
    <h1>Welcome!</h1>
</body>
</html>

Step 2: controller. @Controller is a stereotype annotation (like @Component, @Service), so Spring also creates a bean. A controller action is a method run for a specific HTTP request. It returns the view name.

@Controller
public class MainController {
    @RequestMapping("/home")
    public String home() {
      return "home.html";
    }
}

Open http://localhost:8080/home and you see the heading "Welcome!". Without the /home path you get HTTP 404 Not Found.

Questions the author hears from students, answered later in the book:

  1. Can the method do something other than return a file name?
  2. Can it receive parameters?
  3. Other annotations than @RequestMapping are used on the web; are they better?
  4. Can the page show dynamic content?

Behind the scenes: Spring MVC flow

  1. The client sends an HTTP request.
  2. Tomcat gets it and must call a servlet: the one Boot configured, the dispatcher servlet.
  3. The dispatcher servlet is the front controller: the entry point of the Spring web app; Tomcat calls it for every request.
  4. It asks the handler mapping which controller action matches the request (found via @RequestMapping).
  5. It calls that action. If none matches: 404 Not Found. The action returns the page name (the view).
  6. It asks the view resolver to find the view with that name.
  7. It returns the rendered view as the HTTP response.

The controller is the only component you write; Boot configures the rest. Note: the handler mapping also matches by HTTP method (GET, POST...), left out here and covered in chapter 8.

Author's rule of thumb: "Don't rush into learning details before properly understanding the basics."

Chapter summary (book)

  • Web apps are used more than desktop apps; learn how they work. A web app has a client (frontend) and a server (backend) that processes and stores data.
  • Spring Boot applies convention over configuration and provides defaults for the capabilities you request.
  • Dependency starters = groups of dependencies with compatible versions for one capability.
  • A servlet container (Tomcat) translates HTTP for the Java app; Boot configures it for you.
  • Boot also configures Spring MVC: the components that intercept and manage HTTP requests.
  • You write an HTML document and a controller. @Controller marks the class; @RequestMapping ties an action to a request.
