Lead Developer Career Guide 4: Learning any developer skill

Source: Shelley Benhoff, Lead Developer Career Guide (Manning), ch. 4. Previous: Lead Developer Career Guide 3: Learning lead developer skills. Next: Lead Developer Career Guide 5: Writing technical documentation.

Takeaways
  • Common blockers: information overload, no time to practise, imposter syndrome, impatience, over-ambitious goals.
  • Find your content type (video, written, interactive, samples, podcasts, audiobooks) and your style (visual, auditory, kinesthetic).
  • Boost memory: active recall, teaching, mnemonics, chunking; sleep, stress and mental health matter.
  • Apply skills: personal projects, community/open-source projects, reusable prototypes (a CRUD app).
  • Beat blockers: breaks (about hourly), attainable goals (moonshots as the end goal), ask for help well, rubber-duck it.

Problems developers face

  • Overwhelm by the amount of material; no time to practise or apply.
  • Imposter syndrome; intimidating experienced colleagues.
  • Impatience: goals in one-on-ones are often too aspirational, so you feel you failed and drop them.
  • Even attainable goals slip when life happens; learning is a lifelong journey.

4.1 Improving your learning methods

Understanding how you learn

  • Content types: video tutorials, written tutorials and documentation, interactive coding exercises, code samples, podcasts, audiobooks.
  • Test them:
    • watch a video on a topic, then read documentation on the same topic
    • note which you retain. (The author prefers written tutorials, plus video with written steps, because she started before video existed.)
  • Practise:
    • interactive exercises
    • automate something small (a timekeeping app) and rewrite it in each new language, database or framework
    • read code samples and note where you struggle.
  • Styles: visual (diagrams), auditory (lectures, podcasts), kinesthetic (hands-on). Reflect on which helps you retain.

Boosting your memory

  • Active recall: retrieve without prompts; test yourself or teach someone. Errors that cost you stress to solve become instant recall.
  • Mnemonic devices
Device Definition Example
Acronym word from first letters SOLID (Single Responsibility, Open-Closed, Liskov Substitution, Interface Segregation, Dependency Inversion)
Acrostic sentence whose words' first letters stand for another CRUD = "Careful Reading Uncovers Deeper Meaning"
Chunking break into manageable pieces group long code strings into functions or related variables
Imagery visual image a tree for program hierarchy (trunk = main function, branches = subfunctions)
Rhyme sound correspondence "Agile projects go round and round, with planning, doing, checking, and adjusting to being found"
  • Chunk big tasks: for a mobile app, split into backend and components, each with its own to-do list.

Physical and mental health

  • Sleep, stress and mental health affect how memory consolidates: rest, exercise, nutrition, don't overwork.
  • Imposter syndrome: reframe "I don't know what I'm doing" as "I'm still learning, and that's okay"; focus on what mistakes taught you; consider a therapist or counsellor.
  • Manage stress: exercise, meditation, hobbies, time with loved ones; ask colleagues, friends or professionals for help.
  • Set boundaries:
    • say you want to help but can't now
    • refer to the project manager when overloaded
      • The author, a former people-pleaser, once agreed to an 8 p.m
      • train from London to Belgium for a next-morning client meeting (unsafe, no sleep), later was hospitalised for a week from twice-monthly international travel, kept overworking, and four years later a mental breakdown forced time off
      • "You can't help other people until you help yourself."

Teaching while you learn

  • When you solve a hard error (e.g. a networking error in a local environment, or one found while pair programming), write a blog post, make a video or give a talk.
  • Meetups and user groups: volunteer to speak; error-and-fix talks are engaging; create your own group (organising, scheduling, moderating teaches leadership).
  • Teach a class or workshop online, at a local college or community centre; mentorship programs and apprenticeships (you learn from mentees too).
  • Online: blog, YouTube, podcast, Twitch; also share leadership stories (situation, how you handled it, how you would now).

4.2 Applying your skills

Prototype: an early version used to test and validate design concepts (sketches, mock-ups, wireframes, code). Benefits: explore options early (cheap changes), communicate vision, gain funding and buy-in, align the team.

CRUD application as a universal practice prototype:

Letter What it teaches
Create from conceptualisation to building an app; application architecture and software design
Read reading from an API or database: foundation of user interaction, analysis, reporting
Update business logic and sending data back via a secure API or database connection
Delete secure deletion; what to back up vs delete forever

Personal projects

  • Benefits: build a portfolio; improve problem-solving; increase confidence; try tech you don't use at work.
  • Ideas (table 4.2)
Project Learn
Website or web app HTML, CSS, JavaScript, React or AngularJS
Mobile app Swift (iOS), Kotlin (Android), React Native or Flutter
Game Unity, Unreal, Pygame, Godot
Personal assistant NLP and ML via Dialogflow or Rasa
Chatbot NLP and ML via Dialogflow or Botkit
  • Choose by interest, step outside your comfort zone, follow trends or coding challenges, or solve a problem you or a friend has (contributor Jamie Maguire built a tool on the Twitter API to manage his account).

Community projects

  • Find projects on GitHub, SourceForge, GitLab (code, docs, translation; libraries such as React).
  • Read the documentation first; introduce yourself to maintainers with relevant skills; start small; communicate, ask questions, post updates.
  • Communities: GitHub (code review, issue tracking, project management), Stack Overflow (reputation system), the Linux community.
  • It's about building a network, not only code.

Creating prototypes

  • Start with a CRUD app in a new language, then add advanced features.
  • Translate code between languages: the author learned C# from VB.NET using a VB-to-C# converter plus blogs and textbooks.
  • Reusable assets:
    • a library (e.g. a Python CSV-handling library) or a starter/boilerplate project (React file structure, common libraries, examples)
    • a reference for later
    • good for portfolios
    • improves code quality
    • open source it for feedback.

4.3 Overcoming learning blockers

A learning blocker is normal: the brain needs a break from overload or hit a snag. It doesn't mean you're not capable.

Taking breaks

  • A fresh perspective, rest and recharge, avoiding burnout (working longer on the same thing and getting nowhere). Best ideas come in the shower or bath.
  • Rule of thumb: a break about every hour; do something different (walk, stretch, chat); morning people may need more frequent breaks, night owls can go longer.

Setting attainable goals

  • Be realistic (no mastering React in a week)
    • align with career goals (full-stack = frontend and backend)
    • mix short-term (a language or library) and long-term (expertise, a certification).
  • Measurable and broken down: "learn React" becomes "learn the basics", "build a simple app", "learn advanced features".
  • Moonshot goals are ambitious and transformative; they are the end goal, reached through attainable ones.
Project Moonshot Attainable goals
Build an app the next big social media app learn React basics; build "Hello, world!"; learn advanced React; develop user interactions
Create AGI the next ChatGPT learn AI basics; build a simple algorithm for one task; improve its accuracy and efficiency; study cognitive psychology for human-intelligence models

Seeking help

  • Saves time and frustration; exposes new ways of thinking.
  • How: first research and try on your own; approach colleagues or mentors respectfully; be specific about the problem and background; be open to criticism; thank them.
  • Where: Stack Overflow; GitHub (Issues); Reddit (/r/LearnProgramming, /r/Programming); Quora; dedicated communities (Docker, React, Angular); Meetup.
  • "Seeking help isn't a sign of weakness; it's a sign of strength."

4.4 Case study: Scott Hanselman

(Developer for 30 years; blogging 20 years at hanselman.com; works on .NET and Azure at Microsoft; podcasts Hanselminutes (800 episodes) and Azure Friday (700); has spoken to over 1 million developers in person.)

  • Finding community projects:
    • don't send "let me pick your brain" emails or spam LinkedIn
      • Be prepared first (search projects, follow accounts, interact)
      • "Luck is opportunity plus being prepared." Warm up to people, offer help first, do the grunt work, think about the humans behind the project
    • that builds trust.
  • Overcoming blockers:
    • rubber ducking (explain the problem aloud to a duck, a partner, or yourself on a walk). Be mentally present and use deliberate practice
    • if you don't understand the answers from Google or Stack Overflow (copying async test code without knowing what async means), step back and learn the concept: go one level below your comfort zone.
  • Feeling inadequate: compare yourself only with your past self; people have different lives (kids, jobs); don't apologise for what you're not doing (he plays God of War to relax).
  • Learning style:
    • learn in public (a privilege; ignore mean comments)
    • best in trusted mentoring groups of three to four (e.g. Codenewbie: www.codenewbie.org) where everyone is both mentor and mentee.

Summary points

Assess preferred content types; experiment, practise and reflect; boost memory via active recall, testing, teaching and mnemonics; prototypes save time and communicate ideas; personal projects give experience, portfolio, networking, confidence; beat blockers with breaks, clear attainable goals and help from mentors.
