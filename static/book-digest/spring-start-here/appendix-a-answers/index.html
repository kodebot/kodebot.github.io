Appendix A: Answers to the chapter questions

Source: Laurentiu Spilca, Spring Start Here, Second Edition (Manning, MEAP V05), appendix A. The book's own short answers to the review questions at the end of each chapter, reflowed. Use them for self-testing: cover the answer, answer aloud, compare. Notes: Ch 1: Spring in the real world to Ch 16: Implementing integration tests for Spring apps.

Chapter 1: Spring in the real world

  • Q1. What is an application framework? An application framework is a set of ready-made tools and code that helps you build an application faster instead of writing everything from scratch.
  • Q2. Why do developers use frameworks? They use frameworks to save time, avoid repeating the same code, reduce bugs, and use solutions that are already tested by many developers.
  • Q3. What part of an application is called “business logic”? Business logic is the code that implements what users want to do, such as ordering a product or creating an invoice.
  • Q4. What is “plumbing code”? Plumbing code is the technical code every app needs, like logging, security, database access, and communication between systems.
  • Q5. Why is reusing code better than writing everything yourself? Because it is faster, cheaper, safer, and supported by a large community that has already tested it.
  • Q6. What is the Spring framework? Spring is a popular Java framework used to build many kinds of applications, especially backend applications.
  • Q7. What is inversion of control (IoC)? IoC means the framework controls the creation and use of objects instead of the application doing it by itself.
  • Q8. In what real-world scenarios can Spring be used? Spring can be used for: a. Backend applications b. Automation testing applications c. Desktop applications
  • Q9. Why is community important when choosing a framework? A big community means more help, more examples, and more solutions to common problems.

Chapter 2: The Spring context: Defining beans

  • Q1. What is the Spring context?
    • The Spring context is a place in memory where Spring keeps the objects it manages
    • These objects are controlled by Spring so it can add features like transactions, security, and testing.
  • Q2. What is a bean? A bean is an object instance that has been added to the Spring context. Once it is in the context, Spring can manage it.
  • Q3. Do all objects in an application need to be beans? No. Only the objects that Spring needs to manage must be added to the Spring context.
  • Q4. Why do we add objects to the Spring context? We add objects so Spring can connect its features to them, such as dependency injection, transactions, and testing.
  • Q5. What are the three main ways to add beans to the Spring context?
    • a
    • Using the @Bean annotation b
    • Using stereotype annotations like @Component c
    • Adding beans programmatically with registerBean()
  • Q6. What is a configuration class? A configuration class is a class annotated with @Configuration that tells Spring how to create and manage beans and various other framework-related configurations.
  • Q7. How do you create a bean using the @Bean annotation? You define a method in a configuration class, annotate it with @Bean, and return the object you want Spring to manage.
  • Q8. What is the default name of a bean created with @Bean? By default, the bean name is the same as the method name that creates it.
  • Q9. Can you add more than one bean of the same type? Yes. You can define multiple @Bean methods that return the same type of object.
  • Q10. What happens if Spring finds multiple beans of the same type and you request one by type only?: Spring throws an exception because it does not know which bean to choose.
  • Q11. How can you choose one bean when multiple beans of the same type exist?: a. Refer to the bean by its name, or b. Mark one bean as primary using the @Primary annotation.
  • Q12. What does a primary bean mean? It marks one bean as the default choice when multiple beans of the same type exist.
  • Q13. What is a stereotype annotation? A stereotype annotation (like @Component) tells Spring to automatically create and register an instance of a class as a bean.
  • Q14. What is @ComponentScan used for? It tells Spring where to look for classes annotated with stereotype annotations like @Component.
  • Q15. What is the main advantage of using stereotype annotations? They require less code and reduce boilerplate because Spring creates the bean automatically.
  • Q16. What is the main limitation of stereotype annotations? They can only be used for classes that belong to your application, not for classes from external libraries.

Chapter 3: The Spring context: Wiring beans

  • Q1. What does dependency injection (DI) mean? It means the framework gives an object the dependencies it needs instead of the object creating them.
  • Q2. Why do we prefer dependency injection over creating objects manually? It makes code easier to maintain, test, and change.
  • Q3. What are two ways to create relationships between beans defined with @Bean?: By calling one @Bean method from another, or by letting Spring inject dependencies through method parameters.
  • Q4. What is the role of the @Autowired annotation? It tells Spring to inject a dependency from the context.
  • Q5. What are the three ways you can use @Autowired? Field injection, constructor injection, and setter injection.
  • Q6. Which injection style is preferred in real projects? Why? Constructor injection, because it is clearer, safer, and easier to test.
  • Q7. Why is field injection usually avoided in production code? Because it makes testing harder and does not support immutable fields.
  • Q8. What is a circular dependency? When two beans depend on each other during creation.
  • Q9. How do you usually fix a circular dependency? By redesigning the classes to remove the cycle.
  • Q10. What happens if multiple beans of the same type exist and Spring must inject one?: Spring throws an error if it cannot decide which one to use.
  • Q11. How can you tell Spring which bean to inject when multiple exist? By using @Primary or @Qualifier.

Chapter 4: The Spring context: Using abstractions

  • Q1. What is an interface used for in Java design?
    • An interface defines a contract (the what)
    • Implementations define the how
    • It allows multiple implementations for the same responsibility and helps decouple components.
  • Q2.
    • Why do we use abstractions instead of depending directly on implementations?: To reduce coupling
    • This makes applications easier to change, test, and extend because you can replace implementations without changing dependent classes.
  • Q3. What does it mean that an interface defines “what” and implementations define “how”?: The interface declares required behavior, while implementations decide how that behavior is executed internally.
  • Q4. In a typical Spring application, why do we combine abstractions with dependency injection?: Because most real applications depend on contracts, Spring can inject any bean implementing the required abstraction automatically.
  • Q5. How does Spring inject dependencies when you use interfaces instead of concrete classes?: Spring searches the context for beans created from classes implementing that interface and injects the matching implementation.
  • Q6. Should you annotate interfaces with stereotype annotations like @Component?: No. Spring creates beans from classes, not interfaces. Stereotypes belong on concrete classes.
  • Q7.
    • How do you decide which objects should be managed by the Spring context? Add objects that either: a
    • need dependencies injected, or b
    • are dependencies for other beans, or c
    • need to be augmented by Spring with any capability Spring provides
  • Q8. Why is it usually unnecessary to add simple data objects (like POJOs) to the Spring context?: Because if Spring does not add framework value (DI, lifecycle, proxies, etc.), adding them increases complexity without benefit.
  • Q9. What happens if multiple beans implement the same interface and Spring must inject one?: Spring throws an error unless you explicitly specify which implementation to use.
  • Q10.
    • How can you tell Spring which implementation to inject when multiple exist? Use: a
    • @Primary - default implementation b
    • @Qualifier - choose specific implementation by name
  • Q11. What is the purpose of stereotype annotations like @Service and @Repository?: They still create beans, but also communicate architectural responsibility, improving readability and design clarity.
  • Q12. When should you use @Service instead of @Component? When the class implements use-case/business logic responsibilities.
  • Q13. When should you use @Repository? When the class is responsible for persistence or data access.

Chapter 5: The Spring context: Bean scopes

  • Q1. What does bean scope mean in Spring? It defines how Spring creates and manages bean instances.
  • Q2. What are the two main bean scopes in standard Spring apps? Singleton and prototype.
  • Q3. Which bean scope is the default in Spring? Singleton.
  • Q4. What does singleton scope mean in Spring? Spring creates one instance per bean name and reuses it.
  • Q5. Can Spring have multiple singleton beans of the same type? Yes, if they have different bean names.
  • Q6. Why should singleton beans usually be immutable? Because multiple threads can use the same instance.
  • Q7. What problem can happen if a singleton bean is mutable? Race conditions if the bean attributes can be changed by multiple concurrent threads.
  • Q8. What is eager instantiation? Spring creates beans when the context starts.
  • Q9. What is lazy instantiation? Spring creates the bean only when first used.
  • Q10. Which instantiation type is the default? Eager instantiation.
  • Q11. Why is eager instantiation usually preferred? Better startup validation and faster runtime access.
  • Q12. When might lazy instantiation be useful? When startup time or memory usage is important.
  • Q13. What does prototype scope mean? Spring creates a new instance every time you request the bean.
  • Q14. When should you consider prototype scope? When the bean is mutable or stateful.
  • Q15. Should every object be a Spring bean? No. Only if Spring needs to manage it to augment it with certain capabilities.

Chapter 6: Using aspects with Spring AOP

  • Q1. What is an aspect in Spring? An aspect is a piece of logic that Spring executes when specific methods are called.
  • Q2. What is an advice? Advice defines when the aspect logic runs (before, after, around, etc.).
  • Q3. What is a pointcut? A pointcut defines which methods Spring should intercept.
  • Q4. What is weaving? Weaving is the mechanism by which Spring wraps a target object in a proxy and applies the aspect logic.
  • Q5. Why must the target object be a Spring bean? Because Spring can only apply aspects to objects it manages in the application context.
  • Q6. What annotation enables aspect support in a Spring application? The @EnableAspectJAutoProxy annotation.
  • Q7. What annotation marks a class as an aspect? The @Aspect annotation.
  • Q8. Does @Aspect automatically make the class a Spring bean? No. You must still add it as a bean using @Bean or a stereotype annotation.
  • Q9. What is the purpose of @Around advice? It allows you to execute logic before and after the method and control whether the method is called.
  • Q10. What happens if you don’t call proceed() in an @Around advice? The intercepted method is never executed.
  • Q11. Can an aspect access method parameters? Yes. You can get them using joinPoint.getArgs().
  • Q12. Can an aspect access the method’s return value? Yes. With @Around or @AfterReturning.
  • Q13. How do you intercept methods annotated with a custom annotation? By using a pointcut expression like @annotation(MyAnnotation).

Chapter 7: Understanding Spring Boot and Spring

  • Q1. What is a web application? A web application is an app you use through a web browser. It runs on a server, and you access it over the internet.
  • Q2. What are the two main parts of a web app architecture? The client (frontend), which the user sees, and the server (backend), which processes data and logic.
  • Q3. What’s the client (frontend) role in a web app?
    • The client sends requests to the server and shows the response to the user
    • The client also interacts with the user and offers the user a GUI.
  • Q4. How do the client and server communicate? They communicate using HTTP, where the client sends a request, and the server sends a response.
  • Q5. Why is concurrency important in web apps? Because many users can use the app at the same time, the backend must handle multiple requests safely.
  • Q6. What are the two main ways to design a web app? Backend returns full views (HTML), backend returns data, and frontend builds the UI
  • Q7. What is frontend-backend separation? It means the backend sends only data, and a separate frontend app decides how to display it.
  • Q8. What is a servlet container? A servlet container is a tool that understands HTTP and translates requests into Java method calls.
  • Q9. What is a servlet? A servlet is a Java object that handles requests and builds responses.
  • Q10. What is Spring Boot? Spring Boot is a tool that helps you build Spring apps faster with less configuration.
  • Q11. What is a dependency starter?
    • A dependency starter is a group of dependencies for a specific feature, like web or security
    • Dependency starters remove the need to manually choose and manage many dependencies and versions.
  • Q12. What is autoconfiguration in Spring Boot? It is when Spring Boot automatically configures your app based on the dependencies you add.
  • Q13. What does “convention over configuration” mean? Spring Boot uses common defaults, so you write less configuration code.
  • Q14. What is a controller in Spring MVC? A controller is a class that handles HTTP requests and returns responses.
  • Q15. What does @RequestMapping do? It links a controller method to a specific HTTP path (URL).

Chapter 8: Implementing web apps with Spring Boot and

Spring MVC

  • Q1. What is a dynamic view? A dynamic view is a page that can show different content for different requests. The page stays the same, but the data on it can change.
  • Q2. Why do we need dynamic views? We need them because most real apps do not show the same data to everyone all the time. A page often depends on the user or on the request.
  • Q3. How does the view know what to display? The controller sends data to the view. The view then uses that data to build the HTML response.
  • Q4. What is the role of Model in a controller method? The Model stores the data that the controller wants to send to the view. You add values to it with keys.
  • Q5. What is a template engine? A template engine is a dependency that helps the view use data sent by the controller and display it on the page.
  • Q6. Where do you put a Thymeleaf HTML file? You put it in the resources/templates folder. Static pages go in resources/static, but Thymeleaf templates go in templates.
  • Q7. What are the main ways to send data in an HTTP request? This chapter explains request parameters, path variables, and mentions the request body for larger data.
  • Q8. What is a request parameter? A request parameter is a simple key-value pair sent in the URL query string.
  • Q9. What is a path variable? A path variable is a value placed directly inside the URL path, like /home/blue.
  • Q10. When should you prefer request parameters over path variables? When the values are optional, or when you have more values and want the URL to stay easier to read.
  • Q11. Is the path enough to identify an HTTP request? No. A request is identified by both the path and the HTTP method.
  • Q12. What is an HTTP method? It is a verb that shows the client’s intention, such as getting data, adding data, changing data, or deleting data.
  • Q13. What does GET mean? GET means the client wants to retrieve data without changing data on the server.
  • Q14. What does POST mean? POST means the client wants to send new data to be added on the server side.
  • Q15. What do PUT, PATCH, and DELETE mean? PUT changes a full record, PATCH changes part of a record, and DELETE removes data.
  • Q16. Why can the same path have two different controller actions?
    • Because the HTTP method can be different
    • For example, one action can handle GET /products, and another can handle POST /products.

Chapter 9: Using the Spring web scopes

  • Q1. What is a request-scoped bean? A request-scoped bean is an object that Spring creates for each HTTP request. It exists only during that request and is removed afterward.
  • Q2. Can multiple users share the same request-scoped bean instance? No, each request from any user gets a new instance. This means data is isolated and cannot leak between users.
  • Q3. What is a session-scoped bean?
    • A session-scoped bean is an object that Spring keeps for the entire user session
    • It allows the app to remember data across multiple requests from the same user.
  • Q4. What kind of data should you store in a session-scoped bean?
    • You should store user-related data like usernames or preferences
    • This helps the app remember the user while they navigate.
  • Q5. What kind of data should you avoid storing in session scope?
    • You should avoid storing sensitive data like passwords or secrets
    • Keeping such data for a long time increases security risks.
  • Q6. What is an application-scoped bean? An application-scoped bean is a single instance shared by all users and all requests. It exists if the application is running.
  • Q7. What is a common use case for application scope? A typical use case is counting global events, like the number of login attempts. All users share the same counter.
  • Q8. Why is application scope risky in real applications?
    • It can lead to concurrency problems because multiple users access the same data
    • It can also create performance issues if misused.
  • Q9. What is the main difference between request and session scope?
    • Request scope lives only for one request, while session scope lives across many requests from the same user
    • Session scope helps maintain user state.
  • Q10. Why should you avoid putting too much data in session scope? Because it increases memory usage and can slow down the application. It also makes the system harder to scale.
  • **Q11
    • When should you use a database instead of application or session scope?** You should use a database when data needs to be persistent, shared safely, or scalable
    • It is a more reliable solution for real-world apps.

Chapter 10: Implementing REST services

  • Q1. What is a REST service? REST is a way for two applications to communicate through HTTP. One application exposes endpoints, and another application calls them.
  • Q2. What is an endpoint? An endpoint is a specific HTTP path and method that a client can call. It represents a functionality exposed by the server.
  • Q3. What is the role of Spring MVC in REST services?
    • Spring MVC receives the HTTP request and calls the correct controller action
    • It also creates the HTTP response returned to the client.
  • Q4. What is the difference between a web controller and a REST controller? A web controller usually returns a view name. A REST controller returns data directly in the HTTP response.
  • Q5. What does the @ResponseBody annotation do? The @ResponseBody annotation tells Spring to send the returned value directly in the HTTP response body.
  • Q6. Why is the @RestController annotation useful? @RestController combines @Controller and @ResponseBody. It helps avoid repeating @ResponseBody on every method.
  • Q7. What are the main parts of an HTTP response? An HTTP response contains a status, headers, and a body. These parts help the client understand the result of the request.
  • Q8. How does Spring send Java objects in the response body? Spring automatically converts Java objects to JSON. The JSON is then sent in the HTTP response body.
  • Q9. Why is JSON commonly used with REST APIs? JSON is simple, readable, and supported by many programming languages. It is the most common format used in REST APIs.
  • Q10. What are some common HTTP response statuses?
    • 200 OK means the request succeeded
    • 400 Bad Request means the request data is incorrect, and 500 Internal Server Error means the server failed while processing the request.
  • Q11. Why is exception handling important for REST endpoints?
    • Exception handling allows the application to return meaningful error responses
    • This helps the client understand what went wrong.
  • Q12. What does @RestControllerAdvice do? @RestControllerAdvice centralizes exception handling logic. It allows multiple controllers to share the same exception handling behavior.
  • Q13. What does the @ExceptionHandler annotation do?
    • @ExceptionHandler links an exception type to a method that handles it
    • The method defines the HTTP response sent when that exception occurs.
  • Q14. What is a contract-first approach? In a contract-first approach, developers first describe the API using a contract. The implementation code is generated afterward.
  • Q15. What is the purpose of the @RequestBody annotation? @RequestBody tells Spring to read the HTTP request body and convert it into a Java object.

Chapter 11: Consuming REST endpoints

  • Q1. What is RestClient?
    • RestClient is a modern Spring tool used to call REST endpoints
    • It offers a simple and readable API for sending requests, adding headers, sending a body, and reading the response.
  • Q2. What is the role of a proxy class when consuming a REST endpoint?
    • A proxy class hides the details of the HTTP call from the rest of the application
    • The controller or service calls the proxy method, and the proxy sends the actual HTTP request to the external endpoint.
  • Q3. What is OpenFeign?
    • OpenFeign is a Spring Cloud tool used to call REST endpoints through Java interfaces
    • You define the interface, and OpenFeign creates the implementation for you.
  • Q4. What is the purpose of the @FeignClient annotation?
    • The @FeignClient annotation tells OpenFeign that an interface represents a REST client
    • It also defines important details such as the client name and the base URL of the service being called.
  • Q5. Why should endpoint URLs be stored in properties files?
    • URLs can change from one environment to another, such as development, test, and production
    • Storing them in properties files avoids hardcoding and lets you change the configuration without recompiling the app.
  • Q6. What is RestTemplate?
    • RestTemplate is an older Spring tool used to call REST endpoints
    • Many existing Spring apps still use it, so developers should understand it even if they should usually avoid it in new implementations.
  • Q7. What is WebClient?
    • WebClient is a Spring tool used to call REST endpoints in reactive applications
    • It works with reactive types such as Mono, which represent values that will be produced later.
  • Q8.
    • When should you choose WebClient instead of RestClient or OpenFeign?: You should choose WebClient when the application is designed using a reactive approach
    • For standard non-reactive applications, RestClient or OpenFeign is usually a better and simpler choice.
  • Q9. How can an API contract help when generating a REST client?
    • An API contract describes the endpoint’s method, path, parameters, request body, and response body
    • If the project uses OpenAPI, you can provide the YAML file to the AI tool, so it generates the client based on the real service definition.

Chapter 12: Using data sources in Spring apps

  • Q1. What is a data source? A data source is an object that manages the app’s connections to the database. It helps the app reuse connections instead of creating a new one every time.
  • Q2. Why does an app need a data source? Without a data source, the app would ask for a new database connection for every operation. This would make the app slower and waste resources.
  • Q3. What is JDBC?
    • JDBC is the Java technology that allows an app to work with relational databases
    • It gives the app common objects and interfaces for sending SQL commands and reading results.
  • Q4. What is a JDBC driver?
    • A JDBC driver is a dependency that allows the app to connect to a specific database technology
    • For example, an app needs a MySQL driver to connect to MySQL and an H2 driver to connect to H2.
  • Q5. What is JdbcTemplate?
    • JdbcTemplate is a Spring tool that makes working with a database easier when using JDBC
    • It helps you write less code for common operations, such as adding or reading records.
  • Q6.
    • Which JdbcTemplate method do we use for INSERT, UPDATE, and DELETE operations?: We use the update() method for operations that change data
    • This method can execute SQL commands such as INSERT, UPDATE, and DELETE.
  • Q7. Which JdbcTemplate method do we use to read data?
    • We use one of the query() methods to read data from the database
    • These methods execute a SELECT query and help transform the result into Java objects.
  • Q8. What is a RowMapper?
    • A RowMapper tells the app how to transform one row from the database result into a Java object
    • For example, it can transform a row from the purchase table into a Purchase object.
  • Q9. What is a repository?
    • A repository is a class that contains the logic for working with the database
    • A controller can call the repository, and the repository handles storing or reading the data.
  • Q10. Why do we use BigDecimal for prices instead of double?
    • The double type can lose precision when working with decimal numbers
    • For sensitive values such as prices, BigDecimal is a safer choice.
  • Q11. How can we configure a data source in Spring Boot?
    • We can configure the data source in the application.properties file
    • There, we can set values such as the database URL, username, and password
    • We can also define it programmatically in a configuration class.

Chapter 13: Using transactions in Spring apps

  • Q1. What is a transaction? A transaction is a set of operations that change data and must work as one unit. Either all the operations succeed, or none of them take effect.
  • Q2. Why are transactions important?
    • Transactions help keep data correct when a use case has multiple steps
    • If one step fails, the app can undo the previous changes and avoid inconsistent data.
  • Q3. What does atomicity mean? Atomicity means that several operations are treated as one single operation. If one part fails, the whole operation fails, and the data is restored.
  • Q4. What does commit mean? Commit means that a transaction ended successfully. The app stores all the changes made during the transaction.
  • Q5. What does rollback mean?
    • Rollback means that the app undoes the changes made during a transaction
    • This happens when something fails, and the app needs to restore the data to its previous state.
  • Q6. What happens if all steps in a transaction succeed? If all steps succeed, the transaction commits. This means the app keeps all the data changes made by those steps.
  • Q7. What happens if one step in a transaction fails? If one step fails, the transaction rolls back. The app restores the data to how it was before the transaction started.
  • Q8. How does Spring manage transactions? Spring manages transactions using an aspect behind the scenes. This aspect intercepts method calls and adds transaction logic around them.
  • Q9. What annotation do we use to mark transactional code in Spring? We use the @Transactional annotation. This annotation tells Spring to wrap a method call in a transaction.
  • Q10. Where do we usually place @Transactional?
    • We usually place @Transactional on service methods because service methods implement use cases
    • We can also place it on a service class if all its methods should be transactional.
  • Q11. Do checked exceptions cause rollback by default in Spring?
    • No, checked exceptions do not cause rollback by default
    • By default, Spring rolls back transactions for runtime exceptions.
  • Q12. Can we change Spring’s default rollback behavior?
    • Yes, we can configure @Transactional to roll back for other exception types
    • However, in most cases, it is better to keep the default behavior unless we really need something different.

Chapter 14: Implementing data persistence with Spring Data

  • Q1. What is Spring Data?
    • Spring Data is a Spring project that helps us implement the persistence layer of an application
    • It gives us common contracts and reduces the amount of code we need to write.
  • Q2. Why is Spring Data useful?
    • Spring Data hides part of the complexity of working with different persistence technologies
    • It lets us use a similar approach whether we work with JDBC, JPA, MongoDB, or another technology.
  • Q3. What is a Spring Data module?
    • A Spring Data module is the part of Spring Data made for a specific persistence technology
    • For example, Spring Data JDBC is used with JDBC, while Spring Data MongoDB is used with MongoDB.
  • Q4. What is a Spring Data repository?
    • A Spring Data repository is usually an interface that defines persistence operations
    • Spring Data provides the implementation for this interface at runtime.
  • Q5. What is the Repository interface? Repository is the most basic Spring Data contract. It does not provide any operation, but it marks an interface as a Spring Data repository.
  • Q6. What is CrudRepository?
    • CrudRepository is a Spring Data contract that provides simple operations for creating, reading, updating, and deleting records
    • We use it when the application only needs basic persistence operations.
  • Q7. Why does Spring Data provide multiple repository contracts?
    • Spring Data provides multiple contracts so an application can use only the operations it needs
    • This keeps the design simpler and avoids adding unused operations.
  • Q8. What is the role of the @Id annotation? The @Id annotation marks the field that maps the primary key column. Spring Data needs this information to identify each record.
  • Q9. How can we define a custom repository operation?
    • We can define a custom operation by adding a method to the repository interface
    • Spring Data can sometimes create the query from the method name.
  • Q10. Why is @Query useful? @Query lets us write the exact SQL query used by a repository method. This can make complex operations clearer and easier to maintain.
  • Q11. Why should we prefer @Query for complex operations?
    • Derived method names can become long and hard to read for complex queries
    • Using @Query makes the query explicit and reduces the risk of changing the app behavior by renaming a method.
  • Q12. What is the role of @Modifying? @Modifying tells Spring Data that a query changes data. We use it for operations such as INSERT, UPDATE, or DELETE.

Chapter 15: Unit testing in Spring apps

  • Q1. What is the purpose of a test?
    • A test validates that a specific part of the application works as expected
    • Tests help you find problems early and make sure that future changes don’t break existing behavior.
  • Q2. Why are tests important in an application?
    • Tests are important because applications change all the time
    • When you add features or fix bugs, tests help you check that the old features still work correctly.
  • Q3. What is a unit test? A unit test checks a small piece of logic in isolation. It focuses on one method, class, or small component without using the real dependencies around it.
  • Q4. What are the three main parts of a test?
    • A test usually has three parts: assumptions, execution, and validations
    • First, you define the input and the behavior of dependencies, then you call the method you test, and finally, you check that the result is correct.
  • Q5. What is a mock?
    • A mock is a fake object used in a test
    • You use mocks when you want to control how a dependency behaves so the test can focus only on the logic you want to validate.
  • Q6. What is a happy flow?
    • A happy flow is a scenario where everything works as expected, and no exception or error occurs
    • It is usually the first scenario you test because it represents the normal way the feature should work.
  • Q7. Why should we also test exception flows?
    • Exception flows show what happens when something goes wrong
    • Testing them is important because the app must behave correctly not only when everything works, but also when errors appear.

Chapter 16: Implementing integration tests for Spring apps

  • Q1. What is an integration test?
    • An integration test checks how multiple parts of an application work together
    • It does not focus only on one method or one class, but on the collaboration between components.
  • Q2. What is a Spring integration test?
    • A Spring integration test checks how your code works together with features provided by Spring
    • For example, it can verify dependency injection, configuration, transactions, persistence, security, or other Spring-managed behavior.
