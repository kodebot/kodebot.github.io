Book digests/Spring Start Here

Ch 11: Consuming REST endpoints

Source: Laurentiu Spilca, Spring Start Here, Second Edition (Manning, MEAP V05), ch. 11. Previous: Ch 10: Implementing REST endpoints. Book projects: ssh_ch11_payments (the service being called), ssh_ch11_ex1 to ssh_ch11_ex4.

Takeaways
  • Backends often call other backends: delivery asks invoicing for an invoice, then asks the warehouse to adjust stock.
  • In Spring you do this through a proxy class that wraps one of three clients:
  • RestClient: modern, simple, no extra dependency. The default choice.
  • OpenFeign: write an interface; Spring implements it. Best for larger, structured service-to-service calls (Spring Cloud).
  • WebClient: reactive, non-blocking. Use it only if the whole app is reactive.

Avoid RestTemplate in new code. Even if AI generates the code, you must know the options so you can say which to use and check the result.

11.1 The service being called (ssh_ch11_payments)

Web starter only:

<dependency>
   <groupId>org.springframework.boot</groupId>
   <artifactId>spring-boot-starter-webmvc</artifactId>
</dependency>

// Payment.java
public class Payment {
  private String id;
  private double amount;
  // getters, setters
}

POST /payment takes a request header and a request body, sets a random ID, and returns the payment plus a response header:

@RestController
public class PaymentsController {
    private static Logger logger = Logger.getLogger(PaymentsController.class.getName());

    @PostMapping("/payment")
    public ResponseEntity<Payment> createPayment(
        @RequestHeader String requestId,
        @RequestBody Payment payment) {
      logger.info("Received request with ID " + requestId + " ;Payment Amount: " + payment.getAmount());
      payment.setId(UUID.randomUUID().toString());
      return ResponseEntity.status(HttpStatus.OK).header("requestId", requestId).body(payment);
    }
}

It runs on Boot's default port 8080.

11.2 RestClient (ssh_ch11_ex1)

Preferred in modern Spring: simple, readable API for calling a service, sending data, adding headers, handling responses. Comes with the web starter, no extra dependency.

@Component
public class PaymentsProxy {
    private final RestClient restClient;

    public PaymentsProxy(@Value("${payments.url:http://localhost:8080}") String paymentsUrl) {
      this.restClient = RestClient.create(paymentsUrl);          // base URL
    }

    public Payment createPayment(String requestId, Payment payment) {
      return restClient.post()                                   // HTTP method
            .uri("/payment")                                     // path
            .header("requestId", requestId)                      // headers
            .body(payment)                                       // request body
            .retrieve()                                          // send, get response
            .body(Payment.class);                                // response into a Payment
    }
}
  • ${payments.url:http://localhost:8080} reads a property and falls back to the value after the colon.
  • A proxy (chapter 4's name for an object that talks to something outside the app) holds the call.

An endpoint in the calling app delegates to the proxy:

@RestController
public class PaymentsController {
    private final PaymentsProxy paymentsProxy;
    public PaymentsController(PaymentsProxy paymentsProxy) {
        this.paymentsProxy = paymentsProxy;
    }

    @PostMapping("/payment")
    public Payment createPayment(@RequestBody Payment payment) {
      String requestId = UUID.randomUUID().toString();
      return paymentsProxy.createPayment(requestId, payment);
    }
}

To run both apps on one machine, give this one another port in application.properties:

server.port=9090

curl --request POST \
  --url http://localhost:9090/payment \
  --header 'content-type: application/json' \
  --data '{"amount": 100}'

{
  "amount": 100.0,
  "id": "9ae1db6c-ddb4-4cf9-8319-5c8041935d94"
}

11.3 OpenFeign (ssh_ch11_ex2)

You write an interface and OpenFeign provides the implementation as a bean. The same style appears later in Spring Data. It integrates better with other Spring Cloud features (Circuit Breaker, Load Balancer), so it suits cloud-native systems. Spring Cloud is out of scope; the author recommends Cloud Native Spring in Action by Thomas Vitale (Manning, 2022).

<dependency>
   <groupId>org.springframework.cloud</groupId>
   <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>

The interface is also called the OpenFeign client:

@FeignClient(name = "payments", url = "${name.service.url}")
public interface PaymentsProxy {
    @PostMapping("/payment")
    Payment createPayment(@RequestHeader String requestId, @RequestBody Payment payment);
}
  • name uniquely identifies the client; url is the base URI.
  • Never hard-code URIs or per-environment details. Keep them in application.properties and reference with ${property_name}, so you need no recompile to change environment.
  • It reuses the MVC annotations (@GetMapping, @PostMapping, @PutMapping, @RequestHeader, @RequestBody), nothing new to learn.

Enable it and say where the contracts are:

@Configuration
@EnableFeignClients(basePackages = "com.example.proxy")
public class ProjectConfig { }

The controller is identical to the RestClient one. Call:

curl -X POST -H 'content-type:application/json' -d '{"amount":1000}' http://localhost:9090/payment

{"id":"1c518ead-2477-410f-82f3-54533b4058ff","amount":1000.0}
Received request with ID 1c518ead-... ;Payment Amount: 1000.0     <- payments service log

Legacy: RestTemplate (ssh_ch11_ex3)

Used for years; not for new apps. Not because it is broken, but because needs grew:

  • call endpoints synchronously and asynchronously;
  • less boilerplate and fewer exceptions to handle;
  • retries and fallbacks (logic when a call cannot be executed).

Steps: build HttpHeaders, wrap data in an HttpEntity, call exchange().

@Component
public class PaymentsProxy {
    private final RestTemplate rest;
    @Value("${name.service.url}")
    private String paymentsServiceUrl;

    public PaymentsProxy(RestTemplate rest) {
        this.rest = rest;
    }

    public Payment createPayment(Payment payment) {
      String uri = paymentsServiceUrl + "/payment";

      HttpHeaders headers = new HttpHeaders();
      headers.add("requestId", UUID.randomUUID().toString());

      HttpEntity<Payment> httpEntity = new HttpEntity<>(payment, headers);

      ResponseEntity<Payment> response = rest.exchange(uri, HttpMethod.POST, httpEntity, Payment.class);
      return response.getBody();
    }
}

11.4 WebClient (ssh_ch11_ex4) and reactive apps

  • Built on the reactive approach. The book recommends learning it after the basics (starting point: chapters 12 and 13 of Spring in Action, 6th ed., Craig Walls, Manning, 2022).
  • Spring's docs recommend WebClient, but that only holds for reactive apps. Not reactive: use RestClient or OpenFeign
    • The author disagrees with using WebClient for ordinary blocking calls (a practice many follow)
    • Choosing WebClient is tightly coupled with making the app reactive.

What reactive means (the book's debt-calculation example)

Banking app computes a client's total debt: (1) receive the user id, (2) ask another service whether the user has credits elsewhere, (3) get internal debt, (4) if external debt exists, call an external service, (5) sum and respond.

Two problems with the classic model (one thread runs the whole flow):

  1. The thread sits idle while blocked on I/O but still occupies memory. Ten simultaneous requests could mean ten idle threads.
  2. Steps 2 and 3 are independent yet run one after the other.

Reactive model: treat steps as independent tasks that declare dependencies. Analogy: a backlog of tasks and a team of developers; a developer blocked on one task leaves it and picks another, someone else (or they, later) finishes it. Fewer threads serve more requests, and independent tasks run in parallel.

  • A task returns a producer so others can depend on it; a task uses a subscriber to consume another task's result.

Dependency is WebFlux instead of the standard web starter:

<dependency>
   <groupId>org.springframework.boot</groupId>
   <artifactId>spring-boot-starter-webflux</artifactId>
</dependency>

// ProjectConfig.java
@Configuration
public class ProjectConfig {
    @Bean
    public WebClient webClient() {
      return WebClient.builder().build();
    }
}

// PaymentsProxy.java
@Component
public class PaymentsProxy {
    private final WebClient webClient;
    @Value("${name.service.url}")
    private String url;

    public PaymentsProxy(WebClient webClient) {
        this.webClient = webClient;
    }

    public Mono<Payment> createPayment(String requestId, Payment payment) {
      return webClient.post()
                .uri(url + "/payment")
                .header("requestId", requestId)
                .body(Mono.just(payment), Payment.class)   // body supplied as a producer
                .retrieve()
                .bodyToMono(Payment.class);                // returns a producer too
    }
}
  • Mono
    • is the producer type here: the body arrives as a Mono (an independent task that provides the value) and the method returns a Mono so the framework can subscribe
    • The flow is built from linked tasks, not steps on one thread.
  • Same curl call and output as before.

Sidebar: generating proxy methods with AI

  • Always name the technology (RestClient, WebClient, OpenFeign...); otherwise the agent may pick something that works but does not fit your design.
  • If a proxy already exists, give it as an example so style, dependencies and config stay consistent. If it is your first proxy, say which technology and why.
  • Provide the endpoint contract: the controller method with request and response types, or the OpenAPI YAML if contract-first. This reduces wrong assumptions.

Chapter summary (book)

  • Backends often call other backends' endpoints.
  • Three relevant solutions: RestClient (simple), OpenFeign (Spring Cloud; less code, features suited to modern services), WebClient (reactive).
  • Do not use RestTemplate in new code. Non-reactive: RestClient or OpenFeign. Reactive: WebClient.
  • WebClient is excellent for reactive designs, but you should deeply understand the reactive approach and how to implement a reactive app with Spring before using it.
