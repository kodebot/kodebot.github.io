The Kubernetes Book 3: Getting Kubernetes

Source: Nigel Poulton and Pushkar Joglekar, The Kubernetes Book, 3rd ed. (Packt, 2025), ch. 3. Previous: The Kubernetes Book 2: Kubernetes Principles of Operation. Next: The Kubernetes Book 4: Working with Pods.

Takeaways
  • You need three things for the examples: Docker, a Kubernetes cluster and kubectl. Docker Desktop provides all three.
  • Docker Desktop's cluster cannot run the examples in chapters 8 (Ingress) and 11 (Storage), which need cloud load balancers and storage; use a cloud cluster for those.
  • Choose the kind cluster option (not kubeadm) to get multiple nodes: one control plane node and two workers.
  • The book's cloud option is Linode Kubernetes Engine (LKE): three Linode 2GB nodes; delete it afterwards to avoid cost.
  • kubectl turns each command into an HTTP REST request and uses the kubeconfig file (clusters, users, contexts, current context) to decide where to send it and how to authenticate.

3.1 Install everything with Docker Desktop

Steps in this section:

  1. Create a free Docker account.
  2. Install Docker Desktop.
  3. Deploy its built-in multi-node Kubernetes cluster.

[!note] Licence Docker Desktop is free for personal and educational use. Work use needs a paid licence if the company has more than 250 employees or more than $10M USD annual revenue.

Account and install

  • Sign up for a free Personal account at app.docker.com/signup.
  • You need Docker Desktop 4.38 or newer.
  • Download the installer for Linux, Mac or Windows and follow the prompts; Windows users install WSL 2 when asked.
  • You may need to start the app manually; a whale icon appears in the Mac menu bar or Windows system tray and shows whether it is running.

Verify both tools:

docker --version

Docker version 27.5.1, build 9f9e405

kubectl version --client=true -o yaml

clientVersion:
  major: "1"
  minor: "31"
  platform: darwin/arm64

Enable the multi-node cluster

  1. Click the whale, sign in, then open Settings.
  2. On the General tab, ensure Use containerd for pulling and storing images is enabled (click Apply & restart if needed).
  3. Select Kubernetes, tick Enable Kubernetes and choose kind (sign-in required).
    • The other option, kubeadm, creates only a single-node cluster.
  4. Set the Node(s) slider to 3 and tick Show system containers (advanced).
    • The Kubernetes Dashboard is optional; no example uses it.
  5. Click Apply & restart; it takes a minute or two (Figure 3.1).

If the kind option is missing on 4.38 or later, enter the "Konami code" on the Kubernetes settings page: up, up, down, down, left, right, left, right, b, a. This opens Experimental features, where you enable MultiNodeKubernetes, then retry.

Result: one control plane node and two workers.

kubectl get nodes

NAME                    STATUS   ROLES           AGE   VERSION
desktop-control-plane   Ready    control-plane   10m   v1.32.2
desktop-worker          Ready    <none>          10m   v1.32.2
desktop-worker2         Ready    <none>          10m   v1.32.2
  • In Docker Desktop's Containers tab you will see three containers with the same names: Docker Desktop runs the cluster nodes as containers
    • The user experience is identical (Figure 3.2).
  • This cluster suits most examples, but not the Ingress and Storage examples in chapters 8 and 11.

3.2 Build a Linode Kubernetes Engine (LKE) cluster

  • LKE
    • is a hosted Kubernetes service: Linode builds the cluster and manages availability, performance and updates
    • Hosted services are about as close as you get to a zero-effort production-grade cluster.
  • Other clouds work, but chapter 11's examples are designed for Linode cloud storage, so you must change the storage config files on another cloud.
  • A referral link gives new users $100 free credit, valid 60 days, enough for every example.

Steps:

  1. Sign up for a Linode account.
  2. Create your LKE cluster.
  3. Configure kubectl.
  4. Test your LKE cluster.

Sign up

  • Link: https://bit.ly/4b7YZix (the book also gives the full linode.com/lp/refer/ URL as a fallback).
  • Valid billing info is required in case you exceed the credit or 60 days.
  • The author cannot help if the link fails; sign up from the linode.com home page (you may not get the credit).

Create the cluster

Go to cloud.linode.com, choose Kubernetes, click Create Cluster:

Setting Value
Cluster label tkb
Region One close to you
Kubernetes version A recent version
HA Control Plane No
Control Plane ACL Disabled
Node pools Shared CPU tab, 3 x Linode 2GB nodes
  • An estimated cost is shown (Figure 3.3); click Create Cluster. It takes a minute or two; ready when all three nodes are green.

Configure kubectl

  • kubectl is the command-line tool for every hands-on example; Docker Desktop installs it already. Otherwise search for "install kubectl" for your system.
  • Version skew rule: kubectl must be within one minor version of the cluster. For a v1.32.x cluster, use v1.31.x to v1.33.x.
  • kubectl reads the kubeconfig file, named config, in a hidden .kube folder:
System Location
macOS /Users/<username>/.kube/
Windows C:\Users\<username>\.kube\

If you have no kubeconfig file (no .kube/config at all):

  1. Create a hidden .kube folder in your home directory (leading period).
  2. Download your LKE kubeconfig into it.
  3. Rename it to config, with no extension such as .yaml (you may need to show filename extensions).

If you already have one, rename it, then merge:

  1. Rename the existing file to config-bkp.
  2. Download the LKE kubeconfig into ~/.kube (named tkb-kubeconfig.yaml if you used the book's settings).
  3. Merge and check:
export KUBECONFIG=~/.kube/config-bkp:~/.kube/tkb-kubeconfig.yaml
kubectl config view

apiVersion: v1
clusters:
- cluster:
    certificate-authority-data: DATA+OMITTED
    server: https://127.0.0.1:54225
# <Snip>

You should see the LKE cluster in the cluster, user and context sections. Then flatten into a new config and point KUBECONFIG at it:

kubectl config view --flatten > ~/.kube/config
export KUBECONFIG=~/.kube/config

Finally set the current context so commands reach LKE. With Docker Desktop, click the whale and pick the LKE context under Kubernetes Context. Otherwise:

kubectl config get-contexts

CURRENT   NAME             CLUSTER          AUTHINFO         NAMESPACE
*         docker-desktop   docker-desktop   docker-desktop
          lke349416-ctx    lke349416        lke349416-admin  default

kubectl config use-context lke349416-ctx

Switched to context "lke349416-ctx".

(Your LKE context name will differ.)

Test the cluster

kubectl get nodes

NAME                            STATUS   ROLES    AGE   VERSION
lke349416-551020-184a46360000   Ready    <none>   19m   v1.32.1
lke349416-551020-1c6f99c20000   Ready    <none>   19m   v1.32.1
lke349416-551020-47ad6c5c0000   Ready    <none>   19m   v1.32.1
  • Three nodes with names starting lke.
  • <none> under ROLES: all are workers, because Linode manages and hides the control plane.
  • Otherwise the likely cause is a kubeconfig mistake: redo the steps exactly.
  • Delete your LKE cluster when finished to avoid unwanted cost.

3.3 More about kubectl and your kubeconfig file

Every kubectl command:

  1. Converts the command into an HTTP REST request.
  2. Sends it to the cluster defined in the current-context of your kubeconfig.
  3. Uses the credentials in that current-context.

The kubeconfig (config in ~/.kube) defines four things:

Section Holds
clusters List of known Kubernetes clusters
users List of user credentials
contexts Pairs matching a cluster with credentials
current-context The default context

Example: a context ops-prod combining the ops credentials with the prod cluster; as the current context, all commands go to prod authenticated as ops.

The book's sample file: cluster shield, user coulson, context director (combining them), set as the default:

apiVersion: v1
kind: Config
clusters:                                # all known clusters are listed here
- name: shield                           # friendly name for a cluster
  cluster:
    server: https://192.168.1.77:8443    # cluster's API endpoint (API server)
    certificate-authority-data: LS0tLS...  # cluster's certificate
users:                                   # users are in this block
- name: coulson                          # friendly name (not used by Kubernetes)
  user:
    client-certificate-data: LS0tLS1CRU...   # user certificate/credentials
    client-key-data: LS0tLS1CRUdJTiBFQyB     # user private key
contexts:                                # list of contexts (cluster:user pairs)
- context:
    name: director                       # context called "director"
    cluster: shield                      # send commands to this cluster
    user: coulson                        # authenticate with these credentials
current-context: director                # kubectl will use this context
  • kubectl config view shows the kubeconfig, with sensitive data redacted.
  • kubectl config current-context shows the context in use.
kubectl config current-context

docker-desktop

With Docker Desktop you can switch contexts from the whale menu under Kubernetes Context.

Summary points

  • Docker Desktop gives Docker, a multi-node cluster (kind) and kubectl in one install, and covers most examples.
  • Chapters 8 and 11 need a cloud cluster; the book uses LKE with a $100 / 60-day credit and tells you to delete the cluster afterwards.
  • Other local options the author uses: k3d, KinD, minikube.
  • kubectl plus kubeconfig (clusters, users, contexts, current context) controls which cluster you talk to.
Terms to carry forward
  • Docker Desktop: installs Docker, a cluster and kubectl.
  • kind vs kubeadm (Docker Desktop options): kind gives multi-node, kubeadm gives single node.
  • LKE: Linode Kubernetes Engine, a hosted cluster with a hidden control plane.
  • kubeconfig: ~/.kube/config; clusters, users, contexts, current-context.
  • Context: a cluster plus credentials pair.
  • Version skew: keep kubectl within one minor version of the cluster.
