The Kubernetes Book: Terminology and Outro

Source: Nigel Poulton and Pushkar Joglekar, The Kubernetes Book, 3rd ed. (Packt, 2025), back matter: Terminology and Outro. Previous: The Kubernetes Book 17: Real-World Kubernetes Security.

Takeaways
  • The glossary defines the book's common terms "according to Nigel"; the table below keeps each one, grouped by theme.
  • The Outro explains the cover, why the book draws its own diagram icons, and where to reach the author and leave reviews.

Terminology

The author invites additions: tkb@nigelpoulton.com. The picture ties the workload objects together before the definitions.

Cluster and control plane

Term Definition
Cluster A set of worker and control plane nodes working together to run user applications.
Control plane The brains of every cluster: the API, API server, scheduler, all controllers and more, running on all control plane nodes.
Control plane node A node hosting control plane services; usually runs no user apps; deploy 3 or 5 for high availability.
API Application Programming Interface; in Kubernetes all resources are defined in the API, which is RESTful and exposed via the API server.
API server Exposes the API on a secure port over HTTPS; runs on the control plane.
API group A set of related API resources (networking resources are usually in networking.k8s.io).
API resource All Kubernetes objects (Pods, Deployments, Services) are defined in the API as resources.
Admission controller Code that validates or mutates resources to enforce policies; runs in the API admission chain right after authentication and authorisation.
Cloud controller manager Control plane service integrating with the cloud platform; for example, creating a LoadBalancer Service makes it provision one of the cloud's internet-facing load balancers.
Cluster store Holds cluster and app state; typically etcd; can be deployed to its own cluster for performance and availability.
etcd The open-source distributed database used as the cluster store on most clusters.
Controller A control plane process running as a reconciliation loop, making observed state match desired state.
Reconciliation loop A controller watching cluster state through the API server and ensuring observed state matches desired state; most controllers (such as Deployment) run this way.
Desired state What the cluster and apps should look like (for example five replicas of container xyz on 8080/tcp); vital to reconciliation.
Observed state Also current or actual state: the most up-to-date view of the cluster and apps.
Custom Resource Definition (CRD) API resource for adding your own resources to the Kubernetes API.

Nodes and runtimes

Term Definition
Node / worker node The nodes running user applications; run the kubelet, a container runtime and kube-proxy.
Data plane The worker nodes of a cluster that host user applications.
Kubelet The main agent on every node; watches the API server for new work and keeps a reporting channel back.
Kube-proxy Runs on every node; implements low-level rules routing traffic from Services to Pods, so you send traffic to stable Service names.
Container runtime Low-level software on every node that pulls images and starts and stops containers; typically containerd, Docker or cri-o. Docker was deprecated in 1.20 and support removed in 1.24.
Container Runtime Interface (CRI) Makes runtimes pluggable (Docker, containerd, cri-o, kata and others).
containerd Industry-standard runtime in most clusters; donated to the CNCF by Docker, Inc.; pronounced "container dee".
cri-o A container runtime, commonly used in OpenShift-based clusters.
Container A lightweight environment for modern apps: its own process tree, filesystem, shared memory and more; one container runs one application process.
WebAssembly (Wasm) Secure, sandboxed virtual machine format for executing apps.

Workloads and objects

Term Definition
Pod Smallest unit of scheduling; every container runs in a Pod, which provides a shared execution environment (IP, volumes, shared memory).
Deployment Controller deploying and managing stateless Pods; rollouts, rollbacks, self-healing; uses a ReplicaSet for scaling and self-healing.
ReplicaSet Controller doing self-healing and scaling; used by Deployments.
StatefulSet Like a Deployment, but for stateful applications.
Init container A specialised container that runs and completes before the main app container starts, often to check or initialise the environment.
Sidecar A special container running alongside and augmenting the main app container; service meshes are often sidecars injected into Pods.
Label Metadata on objects for grouping; works with selectors (for example Services send traffic to Pods with matching labels).
Label selector Identifies Pods to act on; for example a Deployment only updates Pods whose labels match its selector.
Annotation Object metadata that can expose alpha or beta capabilities or integrate with third-party systems.
Manifest file YAML holding the configuration of one or more objects; posting it to the API server deploys it.
Namespace Partitions one cluster into virtual clusters; good for quotas and access control, not strong workload isolation.
Orchestrator Software that deploys and manages apps; Kubernetes is the de facto orchestrator of container-based microservices apps.
Microservices A design pattern where app features are small separate apps (containers) communicating via APIs.
Cloud native Loaded term; the author considers an app cloud native if it can self-heal, scale on demand, do rolling updates and possibly rollbacks.

Networking

Term Definition
Service Capital "S": object giving network access to apps in Pods; Pods can fail, scale and be replaced without the endpoint changing; can provision cloud load balancers.
Endpoints object Up-to-date list of healthy Pods matching a Service's selector (the Pods it sends traffic to); may eventually be replaced by EndpointSlices.
Ingress Exposes multiple internal Services over a single external-facing LoadBalancer; layer 7, path-based and host-based HTTP routing.
Ingress class Lets you specify multiple Ingress controllers on a cluster.
Container Network Interface (CNI) Pluggable interface for network topologies; third parties provide plugins for overlay and BGP networks.
Service mesh Infrastructure software for Pod-to-Pod encryption, network telemetry and advanced routing; Consul, Istio, Linkerd, Open Service Mesh and others.

Configuration and storage

Term Definition
ConfigMap Holds non-sensitive configuration; add custom config to a generic container at run time without editing the image.
Secret Like a ConfigMap for sensitive data, inserted into a container at run time.
Volume Generic term for persistent storage.
Persistent Volume (PV) Maps storage volumes on a cluster; external storage must be mapped to PVs before apps use it.
Persistent Volume Claim (PVC) Like a ticket allowing an app to use a PV; combined with StorageClasses for dynamic creation.
Storage Class (SC) Creates storage tiers; for example "fast" (NVMe) and "medium-three-site" (slower, replicated across three sites).
Container Storage Interface (CSI) Lets third-party storage integrate; vendors write a driver or plugin that runs as Pods and exposes enhanced features.

Tools, formats and access

Term Definition
kubectl The command-line tool; sends commands to the API server and queries state through it.
RBAC Role-based access control: determines whether authenticated users can act on cluster resources.
REST REpresentational State Transfer: the common architecture for web APIs, using GET, POST, PUT, PATCH, DELETE.
CRUD Create, Read, Update, Delete: the four basic storage operations.
JSON JavaScript Object Notation: the preferred format for data sent and stored by Kubernetes.
YAML Yet Another Markup Language: what config files are normally written in; a superset of JSON.
K8s Shorthand for Kubernetes: the 8 replaces the eight characters between K and s; pronounced "Kates".
