Understanding Distributed Systems 17: File storage

Source: Roberto Vitillo, Understanding Distributed Systems, 2nd ed. (v2.0.0, 2022), chapter 17. Previous: Understanding Distributed Systems 16: Partitioning. Next: Understanding Distributed Systems 18: Network load balancing.

The one-minute version

Even with a CDN a server's local disk eventually runs out of space for images and videos. Move large static files to a managed file store (AWS S3, Azure Blob Storage): scalable, highly available, strong durability, and the CDN can point straight at it, offloading storage and serving of static resources completely. To see how such stores work, the chapter dissects Azure Storage, which combines partitioning, chain replication and control planes in three layers.

The idea

  • A CDN cut the requests hitting Cruder's server, but local disks have limits
    • Use a managed file store like AWS S3 (https://aws.amazon.com/s3/) or Azure Blob Storage (https://azure.microsoft.com/en-us/services/storage/blobs/#overview) for large static files.
  • They are scalable, highly available, strongly durable
    • A file can be configured so anyone who knows its URL can access it, so you point the CDN straight at the store and completely offload storing and serving static resources to managed services.

17.1 Blob storage architecture: Azure Storage (AS)

Distributed file stores are crucial in modern apps, so it helps to know how they work.

The book dissects Azure Storage, "a scalable cloud storage system that provides strong consistency" ("Windows Azure Storage: A Highly Available Cloud Storage Service with Strong Consistency": https://sigops.org/s/conferences/sosp/2011/current/2011-Cascais/printable/11-calder.pdf).

AS has file, queue and table abstractions; the book covers only the file (blob store) abstraction.

Physical layout. AS is made of storage clusters distributed across regions worldwide. A cluster has multiple racks of nodes, each rack built as a separate unit with redundant networking and power.

Namespace. A global namespace based on domain names with two parts, account name and file name, forming a unique URL: https://ACCOUNT_NAME.blob.core.windows.net/FILE_NAME. The customer sets the account name; AS's DNS server uses it to identify the storage cluster holding the data; the cluster uses the file name to locate the node responsible for it.

Location service (global control plane). Creates accounts, allocates them to clusters, and moves them between clusters for better load distribution.

When a customer creates an account in a region, it: (1) chooses a suitable cluster based on load information; (2) updates the cluster's configuration to start accepting requests for the account; (3) creates a DNS record mapping the account name to the cluster's public IP.

A storage cluster has three layers: stream layer, partition layer, front-end layer.

Stream layer.

  • A distributed append-only file system where data lives in streams
    • A stream is a sequence of extents, and the extent is the unit of replication
    • Writes to extents are replicated synchronously using chain replication (section 10.4).
  • The stream manager is the control plane that assigns an extent to a chain of storage servers
    • When asked to allocate a new extent it replies with the list of storage servers holding a copy; the client caches this and sends later writes to the primary server
    • It also handles unavailable or faulty extent replicas by creating new ones and reconfiguring the replication chains they belong to.

Partition layer.

  • Translates high-level file operations into low-level stream operations
    • The partition manager (another control plane) manages a large index of all files in the cluster
    • Each index entry has metadata (account and file name) and a pointer to the data in the stream service: list of extents plus offset and length.
  • The partition manager range-partitions the index and maps each partition to a partition server
    • it load-balances partitions across servers, splits hot partitions and merges cold ones (range partitioning with dynamic partitioning, chapter 16).
  • It also replicates accounts across clusters asynchronously in the background, used to migrate accounts between clusters for load balancing and for disaster recovery.

Front-end layer. A stateless reverse proxy that authenticates requests and routes them to the right partition server using the mapping the partition manager maintains.

Takeaway. Coarse as this description is, AS "is a great showcase of the scalability patterns applied to a concrete system": partitioning, replication, control planes. Historical note: AS was built from the start to be strongly consistent, while AWS S3 started offering the same guarantee in 2021 ("Diving Deep on S3 Consistency": https://www.allthingsdistributed.com/2021/04/s3-strong-consistency.html).
